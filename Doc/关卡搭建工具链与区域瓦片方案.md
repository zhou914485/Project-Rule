### 1.2 问题

现在 `GroundArtDresser.LoadKits()` 把**用哪套瓦片写死在代码里**：

```csharp
for (int i = 1; i <= 16; i++)
    kit.WallBlocks.Add(L($"Spawn/Wall_Stone_Block_{i:00}"));   // ← 只有出生点
```

所以不管在哪个王国，铺出来都是出生点的石头。要支持 5 个区域，**必须把「用哪套」从代码搬到数据**，并且按**世界坐标**分区——
因为一张分区场景可能横跨两个王国（边界会切在同一个场景里）。

### 1.3 数据模型（两级）

**① `TileRegionKit`（ScriptableObject）** —— 一套材质长什么样

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `DisplayName` | string | 日志 / Inspector 里显示，如「发条王国」 |
| `Blocks` | Sprite[] | 1 格方块，**最少 1 张，建议 16 张**；四个朝向共用 |
| `VariantSeed` | int | 变体哈希偏移，让相邻区域不出现同样的排列 |
| `Props` | GameObject[] | 可选：结构件 prefab（只有魔王城用） |

**② `TileRegion`（MonoBehaviour，挂在 `Grid` 上）** —— 这一片用哪套

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `DefaultKit` | TileRegionKit | 这个场景（= 一个世界分区）默认用哪套 |
| `Overrides` | 列表：`BoxCollider2D` + `TileRegionKit` | 跨王国时用；矩形拖出来，和 `RevealRegion` 同一套编辑器体验 |

查表：`ResolveKit(worldPos)` → 命中某个 override 就返回它，否则 `DefaultKit`；两者都空 → **回退旧的石头套件并告警**（保证老场景不会突然秃掉）。

> 为什么不建一张「全地图区域表」（像 `PartitionCatalog` 那样）：那张表会和场景脱钩，
> 场景一改名/挪位置就失效 —— 分区目录刚踩过这个坑（路径不跟随场景移动）。
> 区域信息住在场景里，跟着场景走，不会漂。

### 1.4 贴图规格（统一约定，别再一图一样）

| 项 | 值 | 理由 |
| --- | --- | --- |
| 落盘 | `Art/Sprites/Tiles/Regions/<Region>/<Region>_Block_01..16.png` | 和现有 `Stone/Spawn/` 同级，一眼看出是区域素材 |
| PPU | 128 | 工程统一（1 格 = 0.5 世界单位 = 64 px） |
| 轴心 | **左下** | 和 `Spawn/Wall_Stone_Block_*` 一致；铺装按格子左下角对齐，旋转靠 `localScale` 归一化 |
| 滤镜 / Mipmap | Bilinear / 关 | 2D 像素风，一致 |
| 尺寸 | 保持原像素（约 64~66） | **不重采样**；铺装时按 sprite 实际尺寸归一化到 1 格 |

> 归一化必须在铺装时做：源块之间有 1~2 px 差异（实测 65×64、66×64 都有），
> 硬编码 0.5 会让墙缝慢慢错开。铺装器按 `cellSize / sprite.bounds.size` 缩放，一块一块算。

### 1.5 铺装器要改的 5 处

1. **删掉 `LoadKits()` 的硬编码**：改为 `TileRegion.ResolveKit(cellWorld)`，每个 run 取一次 kit。
2. **`Kit` 结构**：`WallBlocks` 换成 kit 的 `Blocks`；旧的 `GroundSlabs/SlabSlabs` 只留作回退。
3. **`GroupRuns` 要按 kit 断段**：一条 run 跨两个区域时必须在交界处断开，否则同一段里混两种材质（现在只按「暗墙边界」断）。
4. **`DressBlocks` 加尺寸归一化**（见 §1.4）。
5. **日志**：报告「用到 N 套 kit，各铺 M 件」，方便一眼看出是不是漏配了区域。

### 1.6 实施顺序（可勾选）

- [x] 1. 切片脚本：6 张 sheet → 96 块（发条 16 + 毛绒 16 + 积木 4 色 ×16；出生点早已切好）
- [x] 2. 建 7 个 `TileRegionKit`：`Art/Tiles/Regions/{Spawn,Clockwork,Plush,BrickRed,BrickGreen,BrickBlue,BrickYellow}_Kit.asset`
- [x] 3. `TileRegion` + `TileRegionEditor`（默认套件 + 矩形覆盖，Scene 视图画框、可一键加框）
- [x] 4. 铺装器 5 处全改（数据驱动 / 按 kit 断段 / 归一化缩放 / 变体种子 / 空 kit 回退告警）
- [ ] 5. 每个关卡场景挂 `TileRegion`：**只配了 Level_Start_01 = 出生点**，其余场景待定归属
- [ ] 6. 魔王城：切结构件 → 建 prefab → 加「地图组件」风格的一键放置菜单
- [ ] 7. 验收：同一场景放两个区域，交界处材质分界干净、没有混料、没有缝

### 1.7 需要你（或美术）拍板的两件事

1. **魔王城的地面/墙用什么？** 这套素材只有柱子/平台/王座，没有方块。可选：① 复用出生点石头（省事，但风格不搭）；② 让美术补一套深蓝方块；③ 魔王城整片用「平台岛屿」拼，不做连续地面（设计上最贵，但最有辨识度）。
2. **积木王国 4 个颜色怎么分配？** 4 色是 4 个子区域（每个颜色一片），还是同区域混色（按格随机）？方案默认「4 个子区域」，因为混色会让"积木"看起来杂乱。

### 1.8 已落地的部分（2026-10-18 实测）

| 项 | 结果 |
| --- | --- |
| 切片 | 96 块导入完成（PPU 128 / 左下轴心 / 无 mipmap），尺寸 0.50~0.51 × 0.50 |
| 套件 | 7 个 `TileRegionKit`，每个 16 块 |
| 混铺验证 | 在 `Level_Start_01` 上给 x≥0 加了「发条王国」覆盖盒：重铺后 **748 = 石头 483 + 发条 265**，总数与单区域一致（没有丢件/重件） |
| 分界 | y=−15 那一行材质序列为 `SSSS…SSS|CCCC…CCC`，**切换次数 = 1** —— 一条 run 没有跨区域 |
| 回滚 | 撤掉覆盖盒后重铺回 **748 石头**，与改动前一致 |

> 结论：铺装器已经能按世界坐标分区取素材，交界处干净断段。剩下的是「每个场景归属哪个王国」这种设计信息。

## 2. 工具链现状（审计）

### 2.1 场景骨架：一个关卡场景应该长什么样

菜单 `Tools/规则游戏/在场景里搭好关卡骨架`（Ctrl+Shift+R，`LevelRigBuilder`）负责生成骨架，规则是：

| 物体 | 组件 | 层级 / 排序 | 谁创建 |
| --- | --- | --- | --- |
| `LevelRuntime` | 预制体：Systems + Player + Main Camera + Rule Wheel | — | 骨架菜单（或 `GameRoot` 流式加载） |
| `P4Hud` | HUD 预制体 | — | 骨架菜单 |
| `Grid` | `Grid`（Cell Size **0.5 × 0.5**） | — | 骨架菜单 |
| `Grid/Logic` | `Tilemap` + `TilemapRenderer`(order **−2**) + `TilemapCollider2D` | **Ground 层(8)** | 骨架菜单 |
| `Grid/Art` | 空容器，铺装器往里塞 `SpriteRenderer` | order **1** | 骨架菜单 |
| `Grid/Mask` | `Tilemap` + `MaskLayer` | order **50** | 手动 / 旧场景 |
| `Grid/Ice` | `Tilemap` + `TilemapRenderer`(order **0**) + `TilemapCollider2D`（挂 0 摩擦材质） | — | 铺装器 `⑧` 自动建 |
| `Grid/RevealRtegion_*` | `RevealRegion`（BoxCollider2D 当范围） | — | 手动 |

> `Logic` 必须在 **Ground 层**：玩家的 `Rigidbody2D.Slide` 与接地探测只认这一层，放错层就是"穿过去的空气"。

### 2.2 瓦片种类（逻辑层里能刷什么）

| 瓦片 | 颜色 | Collider Type | 语义 | 谁消费 |
| --- | --- | --- | --- | --- |
| `Ground_Logic` | 白 | **Grid** | 实心几何（墙/地/天花板） | 铺装器 + 玩家碰撞 |
| `Spike_Logic` | 红 | **None** | 刺：不挡路，只判定伤害 | `HazardField` |
| `Secret_Logic` | 青 | **None** | 暗墙：**是**几何，只是会被揭掉 | `SecretWallField` + 铺装器 |
| `Mask_Black` | 黑 | None | 遮罩，刷在 `Mask` 层 | `MaskLayer` + `RevealRegion` |
| `Ice_Logic` | 蓝 | **Grid** | 冰面（0 摩擦），最终住 `Ice` 层 | `SurfaceTile` + `Ice` 层碰撞体 |

调色板 `GroundPalette.prefab` 的格子：`(-1,-1)` Ground、`(-1,-2)` Spike、`(-1,-3)` Secret、`(-1,-4)` Mask、`(-1,-5)` Ice。

### 2.3 铺装器（`GroundArtDresser`）做了什么

菜单（`Tools/规则游戏/铺装美术`）：

| 菜单 | 作用 |
| --- | --- |
| `① 全部`（Ctrl+Shift+G） | 地板 + 墙 + 薄板全铺，管线主入口 |
| `②③④⑤` | 只铺某个朝向（调试/局部重铺用） |
| `⑥ 清空美术`（Ctrl+Shift+H） | 删掉 `Art` 下所有构件 |
| `⑦ 显示/隐藏白盒`（Ctrl+Shift+L） | 切 `Logic` 的 `TilemapRenderer` |
| `⑧ 建冰面层` | 建 `Grid/Ice` + 把逻辑层里的冰面格搬过去 |

管线（一次 `①` 的顺序）：

1. 解析根：选中 `Grid` / `Logic` / `Art` / `Mask` 都行 → 统一往上找到 `Grid`（`ResolveRoot`）
2. **搬冰面**：逻辑层里的 `SurfaceTile` → `Grid/Ice`（同格、高度不变），并踢一下冰面层碰撞体（编辑器里不会自己重建）
3. 清空 `Art`
4. 收集 `solid`：遍历 `Logic` 的 `cellBounds`；跳过刺（`HazardField`）、跳过没声明却 `ColliderType=None` 的瓦片（画错层，告警）
5. 按 **4 个朝向** 分桶：`up/down/left/right` 用**紧邻一格**判断是否暴露；`Space()` 用 64 格上限比较两侧开阔度（决定薄板铺哪一面、厚结构要不要两面都铺）
6. `GroupRuns` 把同朝向的连续格子切成 run（**在暗墙边界断开**）
7. `DressRun`：一条 run 统一选一套件（1 格厚 → 平台套件，否则地面套件）；端点**硬切**不用端帽
8. `DressBlocks`：**一格一块方块**（新素材），按格子哈希挑变体；粗糙边朝外（地板 0°/天花板 180°/左墙 +90°/右墙 −90°）
9. 铺完：关掉 `Logic` 的 `TilemapRenderer`、把遮罩切成纯黑、打日志

三条设计规则（改了会糊）：
- **按 run 选件**，不逐格选（半透明美术重叠会变亮）
- **端点硬切**，不用羽化端帽（端帽会在 Scene/Game 里留灰雾边）
- **厚结构不铺背面**（3 格以上的墙两面都铺会大面积重叠）

### 2.4 瓦片体检菜单（`Tools/规则游戏/关卡瓦片`）

| 菜单 | 作用 |
| --- | --- |
| `① 体检：逻辑层里有哪些瓦片` | 统计种类/数量/范围，发现"遮罩刷进逻辑层"这类事故 |
| `② 把遮罩瓦片移回 Mask 层` | 一键搬迁 |
| `③ 遮罩：半透明 ↔ 纯黑` | 编辑期看效果用（`MaskLayer.SetEditorAlpha`） |
| `④ 清掉逻辑层里的暗墙瓦片` | 暗墙"隐形墙还在刷墙皮"的急救 |

### 2.5 世界分区（多场景）

- `Boot` 场景只有 `GameRoot`，由它创建 `LevelRuntime` 并按 `PartitionCatalog` 流式加载分区场景
- 分区**按世界坐标并排摆放**（同一张大地图切块），加载后自然拼成一整张图
- ⚠️ 坑 1：`PartitionCatalog` 里存的是**场景路径字符串**，场景一挪目录就失效（已经修过一次，改成按 Build Settings 索引判定）
- ⚠️ 坑 2：编辑器里如果分区场景本来开着，流式加载会**再加载一份副本** → 几何体叠在一起。测流式只开 `Boot`
- ⚠️ 坑 3：Tile Palette 的**目标层不随场景切换**，在新场景刷会刷到旧场景的 tilemap 上
- ⚠️ 坑 4（2026-10-19 踩过）：**别把 `Boot` 登记成分区**。Boot 里只有 GameRoot / 主菜单 / 传送服务 / 黑场，没有关卡几何。
  登记进去会让流式加载在玩家离开范围时**卸载 Boot** —— 主菜单、`TrainTravelService`、黑场、线路面板一起消失，
  车站砍不开、也没法传送；再走回范围又会**附加加载第二份 Boot**，新的主菜单 `_started=false` 在玩到一半弹出来暂停游戏。
  代码侧已有两道闸：`WorldStreamer` 认启动场景（`GameRoot` 在 `DontDestroyOnLoad` 之前把路径写进去）永不加载 / 卸载，
  `世界分区/②` 也会拒绝登记 Boot。**分区表是数据，手动加也要拦住。**

### 2.6 实操顺序（从空场景到能跑的一关）

| 步 | 做什么 | 用哪个 | 注意 |
| --- | --- | --- | --- |
| 1 | 搭骨架 | `在场景里搭好关卡骨架`（Ctrl+Shift+R） | 会放 `LevelRuntime` + `P4Hud` + `Grid/Logic/Art`；已有 Tilemap 就跳过地形部分 |
| 2 | 刷几何 | Tile Palette，目标层 **Logic** | 实心用地板瓦片；刺/暗墙/冰面各有专用瓦片（§2.2） |
| 3 | 摆组件 | `地图组件 ①~⑩` 或 `Prefabs/BrickCity`、`Prefabs/Enemies` | 层和 Trigger 见 §3.5；**别把实心组件放进 `RevealRtegion_*`** |
| 4 | 圈揭示区域 | 挂 `RevealRegion`，拖 BoxCollider2D | 异形房间用多个子 Box 拼（§2.1） |
| 5 | 铺装 | `铺装美术/① 全部`（Ctrl+Shift+G） | 会自动搬冰面、关白盒、遮罩转纯黑 |
| 6 | 看效果 | `⑦` 开白盒对照 / Game 视图 | 组件占位可能被地形盖住（§3.6 第 1 条） |
| 7 | 分区 | `世界分区/② 把当前场景登记为分区` | 场景名/路径进 Build Settings，`PartitionCatalog` 会自动补 |

## 3. 组件怎么铺（放在哪一层、什么排序）

### 3.0 层索引（实测，来自 TagManager）

| 层 | 索引 | 谁住这里 |

| `Default` | 0 | 玩家根物体、弹簧的「骑乘者」掩码、冰面层 |

### 3.2 地图组件速查（① ~ ⑩）

| # | 组件 | 主体层 | 体积 | 占位 order | 关键参数 | 耦合点 |
| --- | --- | --- | --- | --- | --- | --- |
| ① | `MovingPlatform` 滑板车 | Ground | 2.5 × 0.4 | −1 | `_start`/`_end`/`_speed`3/`_mode` PingPong/`_waitAtEnds` | `IMovingSurface`（脚本与碰撞体**必须同物体**） |
| ② | `Fan` 风扇 | Wind | 1 × 1（风道 10 × 4，自动设 trigger） | −1 | `_direction`/`_length`10/`_width`4/`_force`150/`_drag`2 | `IWindField`；**禁止旋转**，方向用参数 |
| ③ | `OneWayGate` 单向门 | Ground | 水平：竖板 0.5 × 4 / 竖直：横板 4 × 0.5 | −1 | `_pass`/`_reach`1.5/`_openTint` | 只认 `PlayerController`；放行 = 关自身碰撞体；**形状必须跟方向走**（改方向后点 Inspector 的「重设」） |
| ④ | `BreakableGate` 破门 | Ground | 0.5 × 4 | −1 | `_pass`/`_reach`1 | 订阅玩家 `OnAttacked`/`OnHeavyAttacked` |
| ⑤ | `Tube` 水管 | Ground（根 + 两壁） | 2.5 × 2，壁厚 0.25 | −1 | `_angleDegrees`90/`_turnSeconds`0.35 | 两壁**非 Trigger** 且上下分开，否则报错停用 |
| ⑥ | `SpringPlatform` 弹簧 | Ground（`_riderLayer`=Default） | 板 1.6 × 0.35 | 板 −1 / 柱 −2 | `_springConstant`90/`_launchSpeed`18/`_restLength`2 | `IMovingSurface` + `ISpringSurface` |
| ⑦ | `RailLift` 滑轨 | **仅车厢**在 Ground | 车厢 1.4 × 0.3 | −1 | `_midHeight`/`_riseHeight`1.5/`_sinkDepth`1.5/`_speed`3 | `IMovingSurface`；**不要缩放根** |
| ⑧ | `PushableBody` 铁箱 | **Ground（必须）** | 1 × 1 | −1 | 无序列化参数（`Awake` 强制 Dynamic / 锁旋转 / 连续检测） | `IPushable` + `IMovingSurface`；质量归 `RuleAffectedBody` |
| ⑨ | `ImpactButton` 按钮 | Ground | 座 2 × 1 / 帽 1.6 × 0.45 | 座 −1 / 帽 **0** | `_momentumThreshold`20/`_latching`/`_travel`0.18 | 读 `IMomentumSource`（玩家已实现） |
| ⑩ | `RustyGear` 齿轮 | 无层要求 | 圆 ⌀1.6 | 圆/齿 **0** | `_releaseThreshold`1/`_latching`/`_spinFps`6 | 读 `RuleSystem` 摩擦倍率 |

共同规律：

- 根物体是**空物体**，占位美术在子物体上；**子物体不继承层**，Builder 逐个设（`TubeBuilder` 有注释强调）。
- 占位美术统一用 `P4WhiteboxSquare.png`（1×1 + `localScale` 拉长），颜色语义化（黄=机械、蓝=风、绿=放行…），
  说明牌用 NotoSansCJKsc 字体、order **100**。
- 每个 Builder 都有「起点/终点 = 当前位置」之类的按钮，改完不用手抄坐标。

### 3.5 硬约束清单（Builder 里会报错/静默失败的）

| # | 约束 | 违反后果 |
| --- | --- | --- |
| 1 | 挡路件必须在 **Ground(8)** | 6 个 Builder 直接 LogError + 不生成；玩家会穿过去 |
| 2 | 风扇/风场必须在 **Wind(11)** | 玩家风探测查不到，**白放且无报错** |
| 3 | 单向门/破门/按钮/水管壁/弹簧板**必须实心**（非 Trigger） | 按钮 `Awake` 只会警告；水管会 `LogError` 并停用 |
| 4 | 风扇、揭示区域的碰撞体**必须是 Trigger** | 风扇代码强制；揭示区域 `Awake` 把**所有子** BoxCollider2D 强制 Trigger |
| 5 | 滑板车/铁箱/弹簧：脚本 + 碰撞体 + 刚体**同一物体** | 玩家用 `GetComponentInParent<>` 找接口，分开就找不到 |
| 6 | 滑轨：脚本在根、碰撞体在**子物体车厢** | 反过来车厢不会被带起来 |
| 7 | 水管根必须有 `Rigidbody2D` | 翻转无物理主体 |
| 8 | 组件类（`HazardField`/`SecretWallField`/`MaskLayer`）必须挂在 Tilemap 上 | `RequireComponent` 自动补，但会补到错的对象上 |
| 9 | 风扇禁止旋转、弹簧方向恒竖直、滑轨不要缩放根 | 方向/尺寸会算错 |

### 3.6 组件与铺装的三处真实冲突（实测）

| # | 冲突 | 后果 | 建议 |
| --- | --- | --- | --- |
| 1 | 组件占位美术 order = **−1**，铺装美术 order = **1** | 铺完地形后，**组件会被地形美术盖住** | 组件本体提到 order 0（和玩家/冰面同层），或铺装后单独调 |
| 2 | `RevealRegion` 会把**所有子物体**的 `BoxCollider2D` 强制设成 Trigger | 把实心组件拖到揭示区域子物体下 → **静默失去阻挡** | 组件别放进 `RevealRtegion_*` 的层级里 |
| 3 | 铺装器不知道"这一格有组件" | 组件所在格的几何照样铺满石头，可能和组件穿模 | 需要在组件下方留空 / 手动删那一格的 `Logic` |

> 第 1 条最好在接区域套件时一起解决：把「组件层」定成 order 0，铺装美术保持 1，
> 这样组件永远在地形之上、说明牌 100 之下。
