## 1. 素材实测结论

| 项 | 实测值 |

## 2. 播放逻辑：点击翻页

### 2.1 状态机

```
Idle → 进入第 1 页(淡入) → [黑页? 停一下自己走] → 等待点击 → 转场 → 下一页 …
                                                     └ 最后一页 → 淡出 → 回调
```

- **等待点击**是唯一的等待态；**转场期间不接收输入**，换页 + 淡入结束后再留
  **0.2 s 去抖**（`_inputGrace`）—— 否则一次连点会跳两页。
- 鼠标左键 / 空格 / 回车 / 手柄 A 都算「继续」。
- **ESC = 跳过**（只对开场）：播放期间暂停菜单靠 `AnyOverlayOpen()` 让路，
  所以这一次 ESC 归漫画；开头 0.8 s 不认（`_skipArmDelay`），防止从菜单带过来的按键直接跳过。
  右上角同时有「跳过 ▶▶」按钮。

### 2.2 转场按「与上一页的差异」自动分档

分档**在编辑器里算一次**（导入工具比对像素），运行时只读结果，不做图像比较。

| 档 | 条件 | 表现 | 用在哪 |
| --- | --- | --- | --- |
| **Dissolve** | 相邻页差异 < 10% | 原地交叉溶解 **0.14 s**，不黑场 | 11→12→13、15→16、18→19 |
| **Dip** | 其余换页 | 淡出 0.14 → 黑 0.06 → 淡入 0.18 | 大多数页 |
| **SceneDip** | 场景交界（第 6 / 7 / 10 / 20 页） | 淡出 0.196 → 黑 0.35 → 淡入 0.252 | 5→6、6→7、9→10、19→20 |

**为什么微差组不能黑场**：11→12 的全部信息就是「人没了」。
黑一下再出现，观众读到的是「换了一张图」；原地溶解才读得到「沉下去了」。
反过来说，2→3→4 的叠加页用黑场是**可以**的 —— 那本来就是「一格一格贴上去」的节拍。

### 2.3 黑页（1 / 6）

纯黑页上点击**没有任何视觉反馈**，玩家会以为卡死。所以：

- 黑页标记 `AutoAdvance`，**不占一次点击**，停一下自己往下走；
- 第 1 页停 **0.6 s**（片头留白），第 6 页停 **0.25 s**；
- 判定由导入工具做（平均亮度 < 2% 即视为黑页）。

## 3. 显示

- **16:9 信箱**：UI 根节点底色纯黑，页面 `ScaleToFit` 居中。
  1080p 下实际显示约 **1454 × 1080**，左右各留 233 px 黑边。
  10–17 的外框 `#242424` 与纯黑有可见色阶差 —— 但每次换页都过一次黑，色差被黑场吃掉；
  硬把信箱调成 `#242424` 反而会让 18–21（近黑 / 棕色框）露出灰边。**所以信箱就用纯黑**。
- **两层交叉**：`_imageFront` / `_imageBack` 两张全屏 Image 叠着，
  溶解只改 `opacity`；换页时把下一张塞进**不在用的那一层** —— 单层改贴图会在溶解中途出现硬切。
- **UI 在运行时自建**，不走 Animator / Timeline / UXML：21 张静态图 + 两条透明度曲线，
  用 Playable 要多一份资产、多一条调试路径；而这段 UI 要同时活在 Boot（开场）与分区里（结尾），
  挂预制体还得多一处接线。
- **UIDocument sortingOrder = 240**：仍在暂停菜单（300）之下。
- **播放期间隐藏其它所有 UIDocument**（HUD / 规则轮盘 / 主菜单 / 火车面板）：只改各根节点的
  `display`，不动组件启用状态（别人的 `OnEnable` 缓存不能被重跑），播完原样恢复。
  **不靠 sortingOrder 压**：漫画是整屏黑底 + 一张图，血量条只要还画在任何一个面板里就会浮在黑场上面，
  比没有动画还出戏。

## 4. 数据

```
ComicSequence (ScriptableObject)
  pages: ComicPage[]
    Texture2D image        // 整页贴图
    ComicTransition        // Dip / Dissolve / SceneDip
    bool autoAdvance       // 黑页：不等点击
    float blackHold        // 自动前进前的停留
```

- `Assets/_Project/Resources/Comic/Comic_Intro.asset`（1–19）
- `Assets/_Project/Resources/Comic/Comic_Ending.asset`（20–21）

放在 `Resources` 下是为了**零接线**：`ComicPlayer` 直接 `Resources.Load`。
Inspector 里也能手动指定覆盖（`_intro` / `_ending` 留空才回落到 Resources）。

## 5. 代码落点

| 文件 | 内容 |
| --- | --- |
| `Scripts/UI/Comic/ComicPlayer.cs` | 播放器：状态机、双层淡化、点击 / 跳过、暂停租约、结尾挂钩 |
| `Scripts/UI/Comic/ComicSequence.cs` | `ComicSequence` + `ComicPage` + `ComicTransition` |
| `Scripts/Editor/Comic/ComicArtSetup.cs` | 导入 21 张、压缩设置、比对像素、写两份序列资产 |

改动（小）：

- `MainMenuPresenter.StartGame`：先播开场，**播完才 `StartStreaming`**；没有序列就照旧直接开局。
- `PauseMenuPresenter.AnyOverlayOpen`：认 `ComicPlayer.IsShowing`，ESC 让给漫画。
- `BossEncounter`：新增 **`static event Cleared`**（只在运行时击杀发一次；
  读档恢复成 `Cleared` 走的是另一条路，**不发** —— 所以结尾不会在读档时重播）。

接入点沿用现有约定：

- **暂停**：`TimeManager.SetPaused` + `EntityStatus.SetPaused` + `BlockGameplayInput` 租约，
  **不碰 `Time.timeScale`**；淡入淡出全走非缩放时间。
- **开场**：点「开始游戏」→ 漫画 → 世界开始流式加载。
- **结尾**：Boss 被打死 → 漫画 → 回主菜单。

## 6. 性能（已写进导入工具）

3500×2600 未压缩 = **36 MB/张**，21 张 = **760 MB**。所以：

| 导入项 | 值 |
| --- | --- |
| Texture Type | Default（整屏 UI 图，不切精灵） |
| Max Size | **2048**（1080p 下实际只显示 1454 px 宽） |
| Compression | CompressedHQ |
| Generate Mip Maps | 关 |
| Read/Write | 关 |

≈ **3 MB/张**，21 张合计约 **65 MB**。

## 7. 怎么跑

1. 打开 Unity（工程 `Project-Rule`），等编译完；
2. 菜单 `Tools / 规则游戏 / 剧情漫画 / ① 导入素材并生成序列`
   —— 会复制 21 张到 `Art/Comic/`（改名 `Comic_01..21.png`）、设好导入参数、
   生成两份序列资产，并在 Console 打出每一页的转场分档；
3. 直接 Play：Boot 场景 → 主菜单 →「开始游戏」→ 开场漫画。

不需要拖任何引用、不需要改场景。
