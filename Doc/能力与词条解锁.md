# 能力与词条解锁（2026-10-19）

> 一句话：**能力是玩家实体上的位标记，规则是「属性 × 关系」的交叉积，宝箱只是写入源之一。**

## 1. 能力锁

### 1.1 数据

`PlayerAbility`（`Gameplay/Player/PlayerAbility.cs`）是位标记：

| 位 | 能力 | 锁住时 |
|---|---|---|
| `WallClimb` | 贴墙下滑 + 蹬墙跳 | `WallClimbEnabled` 为 false，滑墙与蹬墙一起失效 |
| `AirJump` | 二段跳 | `MaxAirJumps` 按 0 打包，地面跳 / 土狼跳不受影响 |
| `Attack` | 轻击 / 重击 | 攻击输入被吞掉，攻击盒也不会扳开关 |
| `Throw` | 纸飞机飞刀 | `ThrowKnife` 直接返回 |

能力本身仍是**实体自己的序列化字段**（`_maxAirJumps` / `_wallClimbEnabled` / 攻击参数 / 飞刀预制体），
`_unlockedAbilities` 只是闸门。敌人配了对应字段就有，不受玩家解锁进度限制。

### 1.2 三个读取点

| 位置 | 代码 |
|---|---|
| `PlayerController.BuildTuning` | `MaxAirJumps = HasAbility(AirJump) ? _maxAirJumps : 0`；`WallClimbEnabled = _wallClimbEnabled && HasAbility(WallClimb)` |
| `PlayerController.FixedUpdate` ③′ | `bool attackPressed = input.AttackPressed && HasAbility(Attack);`，轻重击都用它 |
| `PlayerController.ThrowKnife` | 开头 `if (!HasAbility(Throw)) return;` |

`MaxJumps` / `JumpsLeft` 也走同一个判断，HUD 不会显示「还有 2 段跳」。

### 1.3 默认值

- 代码默认 `_unlockedAbilities = All`：现有测试场景（`Test_RuleSystem` 等）不会因为新字段没序列化而突然全锁。
- **正式开局**由 `GameRoot.StartStreaming` 调 `PlayerProgress.StartNewGame()`，把能力设成 `None`。
- 调试场景通常不经过 GameRoot，所以保持全开。

## 2. 规则锁

`PlayerProgress`（挂在玩家身上）实现 `IRuleUnlocks`：

```text
IsUnlocked(attr, rel) = attr ∈ 已解锁属性 && rel ∈ 已解锁关系
```

开局默认：

- 属性：`Gravity`
- 关系：`Revert`

所以只有 **重力 × 反转**。之后每个宝箱解锁**一个属性**或**一个关系**：

- 解锁「摩擦」属性 → 摩擦 × 反转 可用；
- 解锁「质量」属性 → 质量 × 反转 可用；
- 解锁「失效」关系 → 重力 × 失效、摩擦 × 失效、质量 × 失效……都可用了。

规则轮盘不用改：`RuleSelectionSession` 每次实时查 `IsUnlocked`，没解锁的属性只是 `unavailable` 灰化
（`RuleFan.SetAvailable`），不会被隐藏。

## 3. 宝箱

`CityRewardSource` 新增：

| 字段 | 用途 |
|---|---|
| `OpenByAttack` | 勾上 = 必须被攻击盒 / 飞刀打中才开，E 键无效 |
| `Kind` | `Health` / `Energy` / `Ability` / `RuleAttribute` / `RuleRelation`（枚举只在末尾追加） |
| `Amount` | `Kind = Health / Energy` 时生效：**上限提升多少** |
| `Ability` | `Kind = Ability` 时给哪项能力 |
| `Attribute` | `Kind = RuleAttribute` 时解锁哪个属性 |
| `Relation` | `Kind = RuleRelation` 时解锁哪个关系 |
| `SourceId` | 每个场景实例唯一；玩家账本用它记账，回溯不会重复领 |
| `Receiver` | 留空自动找玩家身上的 `PlayerProgress` |

### 3.1 生命 / 能量：直接抬上限（2026-10-20）

`Kind = Health / Energy` 发的是**永久成长**，不是回血回蓝：

- `PlayerProgress.TryGrant` 把 `Amount` 交给同一物体上的 `EntityStatus`
  （`RaiseMaxHealth` / `RaiseMaxEnergy`）；
- `EntityStatus.HealthMax` / `EnergyMax` = 预制体上的设计初值 + 宝箱增量，
  **当前值同步抬高同一段**（读起来是「多出来那截」，不是掉血）；
- 增量记在 `PlayerProgress`（`MaxHealthBonus` / `MaxEnergyBonus`），
  HUD 的 `PlayerVitalsPresenter` 已经订阅 `OnHealthChanged` / `OnEnergyChanged`，会自动刷新；
- `RestoreEnergy` / `ApplyHealthDelta` / `ApplyData` 全部按**含增量的上限** clamp ——
  这一点别退回 `_healthMax` 私有字段，否则回能量会被旧上限截断。

> 战斗力（`Power`，枚举 0 号）已删除：那条奖励没有真正的结算。
> **0 号空着给退役编号**，其余成员编号不动 —— 场景 / 预制体里存的整数因此不用迁移。

### 3.2 存档（已接，2026-10-20）

`PlayerProgress` 实现 `IPlayerProgressStore`（`Infrastructure/Shared/Persistence`），
`PersistenceDriver` 按接口自动找它并交给 `SaveSystem`：

| 存档字段 | 来源 |
|---|---|
| `ClaimedSourceIds` | `PlayerProgress.ClaimedSourceIds`（宝箱 / 龙珠已领编号） |
| `MaxHealthBonus` | 生命上限累计增量 |
| `MaxEnergyBonus` | 能量上限累计增量 |

读档顺序有讲究：`SaveSystem.Apply` 在**玩家数值 `ApplyData` 之前**回灌上限增量 ——
`ApplyData` 会按当时的上限 clamp 生命 / 能量，上限没抬起来的话档里超出的那截会被削掉。
存的是**绝对值**不是叠加量，读两次不会翻倍。

箱子本身不单独存：它的「已开」视觉在 `Awake / Start` 里用 `PlayerProgress.IsClaimed` 回填，
所以流式加载回来、或者跨启动读档，箱子都还是开的。

Inspector 由 `CityRewardSourceEditor` 接管：只显示当前 `Kind` 真正用得到的字段
（能力 / 属性 / 关系三选一，生命 / 能量只画 `Amount`），底部写一句「当前奖励是什么」；
`SourceId` 为空或能力没选会直接给警告。
不会再把三个字段并排摆着让人以为都要填。

攻击入口走 `IContactSwitch.ImpactByContact`，与按钮 / 拉杆同一条路，**不进伤害管线**——
所以「伤害 × 失效」不会把宝箱一起锁掉。

流式加载回来的宝箱会在 `Awake / Start` 用 `PlayerProgress.IsClaimed` 回填「已开」视觉，
不会出现「看起来关着、按 E 没反应」。

## 4. 剑

`SwordInStone` 新增：

- `_requireFreeRule`：默认勾上 = 要求「摩擦 × 反转」；`BoulderSwordMechanism.prefab` **已改成 `0`**
  —— 石头碎掉、剑露出来之后，玩家走进 1.6 米就自动拔，不需要摩擦、也不需要攻击键。
- 其他剑如果还想吃摩擦规则，把 `_requireFreeRule` 勾上即可。
- `_grantAbility`：拔出时解锁哪项能力，默认 `Attack`。走 `PlayerProgress.UnlockAbility`，与宝箱同一个入口。

> 开局链路现在是通的：**重力×反转 → 砸碎巨石 → 靠近拿剑（解锁攻击）→ 用攻击开宝箱 → 摩擦 / 质量 / 失效……**
> 不再需要「第一个宝箱用 E 开」的例外。

## 5. UI：解锁黑幕（2026-10-20 改）

原来是 `PlayerVitalsPresenter` 里的一个 `unlockToast` 标签，2.4 秒自己消失。
现在换成 **`AbilityUnlockOverlay`（`Scripts/UI/Launch/`）**：全屏黑底 + 暂停 + 等玩家按键。

- 事件照旧来自 `PlayerProgress.AbilityUnlocked / AttributeUnlocked / RelationUnlocked`；
- 黑底上写三行：小字「获得新能力 / 获得规则属性 / 获得规则关系」、大字名
  （爬墙跳 / 二段跳 / 攻击 / 飞刀；重力 / 时间 / 摩擦 / 质量 / 伤害·生命 / 因果；反转 / 失效 / 恒定 / 增强 / 削弱）、
  一行说明（能力写用途，词条写「在规则轮盘里和已解锁的×组合使用」）；
- **同时暂停游戏**：`TimeManager.SetPaused` + `EntityStatus.SetPaused` + `BlockGameplayInput` 租约，
  进入时记旧值、退出时恢复；`Time.timeScale` 一行不碰。淡入淡出与等待都走非缩放时间；
- **等新输入**：`PlayerController.AnyGameplayInputThisFrame()`（不受门禁影响），
  ESC / 手柄 Start 也算「继续」—— 所以 `PauseMenuPresenter.AnyOverlayOpen()` 认 `IsShowing` 让路，
  否则同一次 ESC 会先弹暂停菜单、再把黑幕关掉；
- 一次拿到多项时**排队**，一条按一下；
- 淡入 0.25 s / 淡出 0.2 s / 淡入后 0.15 s 宽限（触发奖励的那一下按键不算「继续」）；
- **读档不播**：`PlayerProgress.RestoreUnlocks` 期间不发这三个事件（那不是「刚获得」）。

没有 `PlayerProgress` 的场景（例如 `Test_RuleSystem`）只打 Log，不报错。

## 6. 验证

菜单：`规则游戏 / 验证 / 能力与词条解锁（纯函数 + 预制体接线）`

覆盖 42 项：开局只有重力×反转、解锁属性 / 关系后的交叉积、同编号不重复领取、
攻击宝箱走 `ImpactByContact`、生命 / 能量宝箱抬上限（当前值同步抬高）、同编号不重复叠加、
读档回灌是绝对值、LevelRuntime 的 `PlayerProgress` / 轮盘 `_unlocks` / 开发期开关接线、
  解锁黑幕的元素（`abilityScreen` / `abilityName` / `abilityHint`）与 `Player Vitals` 上的 `AbilityUnlockOverlay`。

存档侧另有 `RuleGame / P1 / 运行存档验证` 的第 10 节（62 项）：宝箱记录与上限增量的往返、新游戏清零。
