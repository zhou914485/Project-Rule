# 关卡瓦片与装饰层方案

> 回答两件事：① 逻辑层怎么新增「刺」这类会伤人的瓦片；② 美术层怎么加前景 / 背景装饰。
> 组件像素尺寸见 [场景组件尺寸标准](场景组件尺寸标准.md)；
> 黑色遮罩与可穿透暗墙见 [黑色遮罩与暗墙方案](黑色遮罩与暗墙方案.md)。

## 0. 现状（先对齐事实）

| 对象 | 组件 | 图层 | 排序 |
|---|---|---|---|
| `Grid` | `Grid`（Cell Size 0.5 × 0.5） | 0 | — |
| `Grid/Logic` | `Tilemap` + `TilemapRenderer` + `TilemapCollider2D`（实心） | 8 Ground | order **-2** |
| `Grid/Art` | 铺装器生成的 `SpriteRenderer` 子物体 | 0 | order **1** |
| 玩家 / 敌人 | `SpriteRenderer` | — | order **0 / 5** |
| 屏幕效果 | `LevelRuntime.prefab` | — | order **100** |

- 排序层只有 `Default` 一个 → 一切靠 **Order in Layer 数值**排序。
- `Logic` 的碰撞体是**实心**的：往里面画的东西默认就是墙。

## 1. 逻辑层新增「刺」瓦片

### 1.1 设计口径

**逻辑层 = 语义层。** 一格可以是「墙」，也可以是「刺」——都是关卡逻辑，只是后果不同。
所以刺**画在同一张 `Logic` Tilemap 里**，用**瓦片资产**区分类型，而不是再开一张 tilemap。

区分手段是瓦片的 `Collider Type`：

| 瓦片 | Collider Type | 含义 |
|---|---|---|
| `Ground_Logic` | **Grid** | 实心墙 / 地面 |
| `Spike_Logic` | **None** | 不挡路，只判定伤害 |

> 刺格 **没有碰撞体**，玩家会直接穿过去并受伤——这才是「碰到就受伤」的正确手感；
> 如果刺是实心的，玩家会被卡住，还要处理「踩在刺上站着」的怪状态。

### 1.2 三步接入

**第 1 步：做刺瓦片资产**

1. Project 窗口选中 `Assets/_Project/Art/Tiles/`
2. 右键 → `Create` → `2D` → `Tiles` → `Tile`，命名 `Spike_Logic`
3. Inspector 里：
   - `Sprite`：`Art/Sprites/Tiles/Logic_Tile`（白盒方块）
   - `Color`：调成醒目的红（例如 #C03A3A），方便和白盒墙区分
   - **`Collider Type`：`None`** ← 关键，漏了刺就变成墙
4. 以后加「锯 / 岩浆」只需再加一个瓦片资产，脚本不用改

**第 2 步：给 `Logic` 挂 `HazardField`**

1. Hierarchy 选中 `Grid/Logic`
2. `Add Component` → `Hazard Field`
3. 在 `Hazards` 列表里加一项：
   - `Tile`：拖入 `Spike_Logic`
   - `Damage`：基础伤害（例如 1）——**填基础值，不要自己乘规则**
   - `Knockback`：击退强度（例如 6）
4. 其余默认值一般不用改：
   - `Scan Interval` 0.05 秒（扫描节奏）
   - `Repeat Interval` 0.5 秒（同一目标两次受伤的最小间隔）
   - `Target Mask`：全部图层（非可受伤目标会被自动忽略）

**第 3 步：画刺**

用 Tile Palette 把 `Spike_Logic` 画在玩家会经过的格子里（例如地板**上面那一格**）。
铺装器（Ctrl+Shift+G）会自动跳过刺格：**不给刺铺墙皮，也不把刺当成实心几何**——
所以刺旁边的墙该有的外露面照旧会有。

### 1.3 为什么不用触发器（重要）

玩家是 **Kinematic 刚体 + `Rigidbody2D.Slide`** 解算位移。Kinematic 刚体默认
**不与静态碰撞体产生接触 / 触发回调**（要开 `useFullKinematicContacts` 才有）。

所以 `HazardField` 走的是**显式重叠查询**（`Physics2D.OverlapBox`）：
和刚体类型无关，也不要求刺格带碰撞体，还能顺手避开「触发器要配 IsTrigger + 刚体」的一堆前置条件。

### 1.4 伤害链路

    HazardField ──基础伤害──► CombatSystem.ApplyDamage ──► DamageProcessor（唯一伤害出口）
                                                              │
                                                              ▼
                                                IDamageable.ApplyDamage（EntityDamageable）
                                                → 抗性 / 无敌帧 / 扣血 / 击退 / 死亡广播

- **只传基础伤害**：缩放 / 反转 / 因果 / 挂账都由 `DamageProcessor` 处理，
  自己先换算会**绕过伤害规则**（工程铁律）。
- **击退方向**：`EntityDamageable` 按「施加方位置」推方向，所以 `HazardField` 每次结算前
  会把内部标记挪到命中的那一格——方向才是局部正确的。
- **暂停**：`TimeManager.Instance.IsPaused` 为真时判定停摆，和物理停步进保持一致。

### 1.5 前置条件（缺一个就不生效）

| 需要什么 | 在哪 | 缺了会怎样 |
|---|---|---|
| `CombatSystem` | 场景 `Systems` | `ApplyDamage` 直接返回 0，不掉血 |
| `RuleSystemDriver` | 场景 `Systems` | `DamageProcessor` 建不出来，伤害静默失效 |
| 目标有 `EntityStatus` + `EntityDamageable` | 玩家 / 敌人身上 | 查不到 `IDamageable`，跳过 |
| 目标实现 `IKnockbackReceiver` | `PlayerController` 已实现 | 只掉血、不击退 |

### 1.6 什么时候该拆成独立 `Hazard` Tilemap

以下任一成立时，把刺挪到 `Grid/Hazard` 独立 tilemap，`HazardField` 直接挂过去即可（脚本不用改）：

- 危险格需要**独立显示**（例如编辑器里单独隐藏刺层）
- 危险种类变多、还想给它们**单独排序**（前景刺 / 背景刺）
- 不想让 `Logic` 的实心碰撞体去 bake 大量 `None` 格（性能上无所谓，纯粹是整洁）

## 2. 美术层：前景 / 背景装饰

### 2.1 层级预算（用 Order in Layer 数值）

| 层 | Order | 说明 |
|---|---:|---|
| `Bg_Far` 远景背景 | -30 | 天空 / 远山 / 视差层 |
| `Bg_Near` 近景背景 | -20 | 墙后装饰、管线、藤蔓底 |
| **提示文字** `WorldHintText` | **-10** | 按键教程 / 机关说明；压在近景背景前、逻辑与角色后（见 [文字提示组件](文字提示组件.md)） |
| `Logic` 白盒 | -2 | 逻辑层（铺完自动隐藏） |
| 玩家 | 0 | 现状 |
| `Art` 地形美术 | 1 | 铺装器产物 |
| 敌人 | 5 | 现状 |
| `Fg_Decor` 前景装饰 | **20** | 挡在玩家和敌人前面 |
| 屏幕效果 | 100 | `LevelRuntime` 的淡入淡出，装饰不要超过它 |

> ⚠️ `Art` 现在是 **1（高于玩家 0）**。好处是墙皮绝对盖住白盒；代价是贴墙时
> 墙皮可能盖住玩家伸出去的剑 / 围巾。**想改成玩家永远在墙前，把
> `GroundArtDresser.ArtSortingOrder` 调成 -1**（仍然高于 `Logic` 的 -2，满足「美术盖住逻辑」）。

### 2.2 三种加法，按用途选

| 用途 | 做法 | 为什么 |
|---|---|---|
| 重复性瓦片（草、砖、藤、背景填充） | **Tilemap + Tile 资产** | 可以刷、可以批量改，和 `Logic` 共用 0.5 网格 |
| 一次性道具（火把、吊链、前景灌木） | **`SpriteRenderer` 物件 / Prefab** | 需要自由旋转缩放、可能要挂动画或组件 |
| 会动的装饰（飘旗、灯） | **Prefab + 动画** | Tilemap 放静态图，动画交给 Prefab |

### 2.3 建装饰层（Tilemap 路线）

1. Hierarchy 右键 `Grid` → `2D Object` → `Tilemap` → `Rectangular`，命名 `Bg_Decor`；
   同样再建一个 `Fg_Decor`
2. 各自的 `TilemapRenderer` 设置：
   - `Sorting Layer`：`Default`
   - `Order in Layer`：`Bg_Decor` = **-20**，`Fg_Decor` = **20**
3. **不要**给装饰层加 `TilemapCollider2D`（装饰不挡路）
4. 用 Tile Palette 刷装饰瓦片；瓦片资产照 §1.2 第 1 步做，`Collider Type` 留 `None`

### 2.4 为什么不要直接塞进 `Art`

`GroundArtDresser` 每次铺装都会 **清空 `Art` 的所有子物体**再重建。
把装饰放在 `Art` 下面，按一次 Ctrl+Shift+G 就全没了。

所以装饰要么放**独立的 Tilemap**（`Bg_Decor` / `Fg_Decor`），
要么放**独立的 SpriteRenderer 根**（例如 `Grid/Decor_Bg`、`Grid/Decor_Fg`）——
两者都不在 `Art` 子树里，铺装器不会碰。

- ✅ **菜单选中 Grid 或它下面的任意子物体都行**（Logic / Mask / Art 都可以）：内部会往上找到 Grid。
  以前只有「选中 Grid」才对，选中 `Logic` 时铺装会把美术建到 `Logic/Art` 下、和 `Grid/Art` 各存一份，
  「清空美术」再去清 `Grid/Art` 就显得没反应。

### 2.5 装饰瓦片尺寸

沿用 [场景组件尺寸标准](场景组件尺寸标准.md)：**一格 = 64 × 64 px，PPU = 128，0.5 × 0.5 world unit**。
多格装饰按整数格交付；Pivot 用左下角 (0,0)（与 `Logic` 的 `CellToWorld` 对齐）。

## 8. 冰面（摩擦 0，单独一层）

### 8.1 结构

冰面**单独一层** `Grid/Ice`，不放在 `Logic` 里。原因是物理属性跟着**碰撞体**走：
一整张 Tilemap 只有一个碰撞体，和地面同层就没法逐格设摩擦
（玩家能被代码蒙混过去，但**物理驱动的物体**——石头、投掷物——在冰上不会打滑）。

| 项 | 值 |
| --- | --- |
| 图层 | `Grid/Ice`（Tilemap + TilemapRenderer order **0** + TilemapCollider2D） |
| 物理材质 | `Assets/_Project/Data/Config/Ice_Surface.physicsMaterial2D`（friction **0**） |
| 瓦片资产 | `Assets/_Project/Art/Tiles/Ice_Logic.asset`（`SurfaceTile`，Collider Type = Grid） |
| 贴图 | `Assets/_Project/Art/Sprites/Tiles/Ice_Tile.png`（64×64 / PPU 128 = 正好一格） |
| 调色板 | `GroundPalette` 的 `(-1,-5)` 格 |

### 8.2 怎么用（一步）

1. Tile Palette 选 `Ice_Logic`、目标层仍然选 **Logic**，直接盖在地面那一行上
2. 跑 `Tools/规则游戏/铺装美术/① 全部` —— 它会**自动把逻辑层里的冰面格搬到 Ice 层**
   （同一格、高度不变、碰撞归冰面层），然后正常铺石头
3. 也可以手动跑 `⑧ 建冰面层（0 摩擦）`：建层 + 搬迁，不重铺美术

> 铺装器搬完会顺手把冰面层的 TilemapCollider2D 关一下再开：编辑器里没有帧循环，
> 碰撞体不会自己重建形状，不踢一下会「看得见但踩空」。

### 8.3 摩擦规则如何作用于冰面

| 规则 | 普通地面 | 冰面 |
| --- | --- | --- |
| 摩擦 × **减弱**（0.3） | 减速度 40 → 12 | **无效**（0 × 0.3 还是 0） |
| 摩擦 × **加强**（3.0） | 40 → 120 | **抓地补到 1** → 40（= 普通地面） |
| 摩擦 × **反转** | 按键方向翻转 | 同样生效 |

加强那一档靠 `VelocitySolver.Horizontal` 里这几行实现：

```csharp
float grip = frame.Contact.GroundFriction * frictionScale;
if (frictionScale > 1f)
    grip += 1f - Mathf.Min(frame.Contact.GroundFriction, 1f);   // 冰面 ×加强 → grip = 1
```

纯乘法做不到这件事（0 × 3 = 0），所以加强时按「离完全打滑还差多少」补一份抓地；减弱刻意不补。

### 8.4 美术

冰面**不参与铺装**：铺装器跳过它，冰面层自己渲染（order 0，白盒 −2、美术 1 之间）。
所以**改冰面长什么样 = 换 `Ice_Tile.png`**，不用碰美术套件。
