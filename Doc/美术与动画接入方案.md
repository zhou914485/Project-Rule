## 二、导入设置（已定）

| 项 | 值 | 理由 |
| --- | --- | --- |
| Texture Type | **Sprite (2D and UI)** | — |
| Sprite Mode | **Single** | 每帧一个文件，不做图集切片 |
| **Pixels Per Unit** | **640** | 见下 |
| Filter Mode | **Bilinear** | ⚠️ **这是手绘线条画，不是像素画**——Point 会让线条出锯齿 |
| Generate Mip Maps | **关** | 2D |
| Alpha Is Transparency | **开** | — |
| Pivot | **Custom**（见 §三）| 每个序列不同 |

### PPU = 640 是怎么来的

- 摄像机 `orthographic size = 4` → 屏幕高 **8 世界单位**
- 玩家胶囊碰撞箱 **1×1 单位**（白盒精灵也是 1 单位）
- 角色站立帧实测 **699 px 高** → `699 / 640 = 1.09 单位`
  → 比碰撞箱高 9%（头发略出头），**碰撞箱、摄像机、关卡尺寸全都不用动** ✓

### 🔴 未解决：纹理内存

裁切后仍有 **≈1.3 亿像素**、212 张贴图：

| 方案 | 显存占用 |
| --- | --- |
| 当前分辨率（PPU 640）| 未压缩 ≈ **520 MB** / DXT5 ≈ 130 MB ✗✗ |
| **整体缩小 4 倍 → PPU 160** | 未压缩 ≈ 32 MB / DXT5 ≈ 8 MB ✓✓ |

**世界里的尺寸完全不变**（缩小 4 倍 + PPU 除以 4 = 同样的世界大小），
而 1080p 下角色约显示 147 px，贴图留 175 px → 1.2 倍超采样，够用 ✓

## 三、轴心（已定）

### 规则：**脚底中点** —— `pivot = (质心x, 裁切框底边)`

- **x 用 alpha 质心**，不用包围盒中点。围巾是飘起来的、剑是伸出去的，
  它们会把包围盒拽偏，但**质量集中在身体上**，质心稳。
- **y 用底边**（脚）。
- 裁切：每个序列裁到「**该序列所有帧的并集包围盒**」——
  ⚠️ **不是按帧裁**。序列内部的帧间位移是**故意的**（挥剑前冲、翻滚），按帧裁会把动作裁没。

### ⚠️ 为什么不给空中姿势特判

翻滚姿势（`Airborne` / `Land` / `WallJump` / `Weightless`）是卷身动作，
脚是收起来的，所以「底边 = 脚」并不严格成立。

但**空中没有地面线可以比对** —— 那里差几十像素谁也看不出来；
而**落地姿势的脚必须踩在地面线上**，那才是必须对的地方。
所以统一用一条规则，不为空中姿势搞特例 ✓

## 四、谁驱动动画（已定）

**`PlayerController` 不认识 Animator。** 中间隔一层 **`PlayerAnimationDriver`**
（`Scripts/Presentation/Player/`）：

```
PlayerController ──只读状态 + 边沿事件──► PlayerAnimationDriver ──参数──► Animator（自己管过渡）
```

`RuleGame.Presentation` 的 asmdef 已依赖 `RuleGame.Gameplay` ✓（表现层依赖玩法层，单向）。

### ① 持续条件：每帧重写

| 参数 | 来源 |
| --- | --- |
| `Speed` (Float) | `\|Velocity.x\|` |
| `Grounded` (Bool) | `IsGrounded` |
| `Dashing` (Bool) | `IsDashing` |
| `WallSliding` (Bool) | `IsWallSliding` |
| `GravityFlipped` (Bool) | `Physics2D.gravity.y > 0` |
| `Rising` (Bool) | `Dot(Velocity, 沿「上」) > 0.1` |

### ② 边沿事件：由玩法层发 Trigger

⚠️ **这几个必须由 `PlayerController` 发事件，不能靠采样推导** —— 0.33 秒的落地只有 4 个物理帧，
每帧采样会漏掉或多算一次。

| 事件 | 发在哪 |
| --- | --- |
| `OnJumped` | `FixedUpdate` ⑦ 地面跳 / 空中段各自的分支末尾 |
| `OnWallJumped` | ⑦ 蹬墙跳分支末尾 |
| `OnLanded` | ① 接地的 `false → true` 那一刻 |
| `OnDashed` | `UpdateDash` 里冲刺真正开始的那一行 |

受击 / 死亡不另加事件：driver 订阅 `EntityStatus.OnHealthChanged`，
掉血 → `Hurt`、掉到 0 → `Die`（回血不触发），从 0 回到正数（复活 / 快照回滚）→
`Animator.Play("Idle")` 拉回初始态。

**死亡动画与复活是握手的**：`Die` 是终点状态、没有出边（播完停在最后一帧），所以
① 倒下时 driver 调 `PlayerController.HoldRespawn()`，玩法层即便 `_respawnDelay` 到点也不许复活；
② 状态 `Die` 的 `normalizedTime >= 1`（整段播完）时调 `ReleaseRespawnHold()`，玩法层才 `Respawn()`；
③ 复活瞬间（血量 0 → 正数）driver 再 `Play("Idle", 0, 0f)` 把状态机拉出 `Die`，并清掉残留 Trigger。
`Hero_Die` 32 帧 @ 12fps = 2.667 秒，只靠 `_respawnDelay`（1.2 秒）会在人还没倒下时瞬移走。
兜底：动画图里没有 `Die`（换过控制器）时 1 秒后放行，不会把复活卡死。

受伤或死亡演出期间由 driver 维护 `Reacting`，普通机动和攻击的 AnyState 过渡要求它为 false。仅排列过渡优先级不能阻止下一帧打断受伤；触发受伤时还会清除旧动作 Trigger，演出期间丢弃新的普通动作动画事件，避免结束后补播。死亡仍可打断受伤。这只保护动画播放，不新增玩法硬直或无敌。已有图可用 `RuleGame/Animations/修复 Hero 受伤动画打断规则（保留现有动画图）` 增量修复，完整重建也会生成相同条件。

### ③ 暂停与翻转

`animator.speed = IsPaused ? 0 : 1` —— D18 用 `Physics2D.simulationMode` 停物理、**不改** `timeScale`，
所以动画必须显式停；`flipX = Facing < 0`。

## 五、状态机路线：**参数驱动 + Animator 图**（2026-10-13 改定）

### 分工：C# 发意图，Animator 管过渡

这套分工与《空洞骑士 / 丝之歌》一致 —— 那边的 PlayMaker FSM 只做「决策」，
过渡、混合、播完再走交给 Unity Animator。我们不需要 PlayMaker（决策本来就在 C# 里），
但**桥要发「意图」，不是「状态名」**：

| | 旧做法（已废） | 现做法 |
| --- | --- | --- |
| driver 干什么 | 每帧算出状态 hash，`CrossFade` 过去 | `SetFloat` / `SetBool` / `SetTrigger` |
| 过渡条件写在哪 | C# 的 if-else | **Animator 图** |
| 「播完再走」 | 手写 `_oneShot` 标志 | **`Has Exit Time`** |
| 「谁能打断谁」 | if 的顺序 | **`AnyState` 过渡的顺序** |

> ⚠️ **为什么不用 2D Blend Tree 混 Walk/Run**：Blend Tree 靠「按权重插值曲线」工作，
> 而精灵帧是**对象引用曲线**（`SpriteRenderer.m_Sprite`），Unity 对它**不做插值** ——
> 于是它在 Idle/Walk/Run 之间等于**没有过渡地硬切**，比 transition + 交叉淡入更生硬。
> Blend Tree 适合骨骼动画，不适合精灵序列。

### 图由脚本生成，脚本进仓库

`Scripts/Editor/Animations/HeroAnimatorBuilder.cs`
（菜单 **`RuleGame/Animations/重建 Hero 动画图`**）用 `UnityEditor.Animations`
从一份**声明**建出整张图（23 个 state、41 条过渡、11 个参数）。

- **好处**：`.controller` 是二进制、git 里没法 review；把图写成 C# 之后，
  「谁在什么时候切到谁」也能 diff、能 blame。
- **它是真相源**：在窗口里手调之后请回填声明；下次重构重跑脚本。
  ⚠️ **重跑会覆盖窗口里的手改**。
- 控制器 **GUID 不变**（原地重建），场景引用不会断。
- 参数名引用 `PlayerAnimationDriver` 上的 `public const`，图和代码不会各说各话。

### 打断优先级（`AnyState` 的列表顺序 = 优先级）

```
死亡 > 受击 > 冲刺 > 蹬墙跳 > 起跳 > 落地
```

## 七、朝向与翻转（已定）

### 朝向：**直接用 `PlayerController.Facing`，不需要额外检测**

`_facing` 在接地分支里取的是**换算后**的方向，所以「摩擦 × 反转」时你按右往左走，
`Facing` 自动是 −1、精灵自动朝左 ✓ **方向检测这件事已经做完了** ✓

### 翻转：**`spriteRenderer.flipX = Facing < 0`**

不翻 `Visual` 子物体的 scale，也不翻根物体：

| 做法 | 评价 |
| --- | --- |
| **`flipX`** | ✅ 一行；绕精灵自己的轴心镜像，精确；不碰 transform |
| 翻 `Visual` 子物体 scale | 整棵子树跟着翻（挂武器/特效点自动镜像）—— 但**目前没有需要翻的子物体** |
| 翻**根物体** scale | ❌ 会连碰撞箱一起翻；Rigidbody2D 上挂负缩放 Unity 会警告 |

因为**剑是画在帧里的**（拔剑/挥剑/收剑整套都是角色帧，没有单独的武器物体）✓ 所以 `flipX` 够用。

> 📌 以后若加了「特效挂点」这类子物体，`flipX` 不会翻它 —— 那时再换 `Visual` 方案。

## 八、重力反转 / 暂停（已定）

### 重力反转：**用专门的动画，不做 `flipY`**

`Weightless`（失重倒转，14 帧）就是为这个准备的 ✓
driver 读到重力被反转（`Physics2D.gravity` 与默认反向）时播它，**不翻精灵**。
（这比「先不颠倒」更好 —— 美术已经给了正向的表达。）

### 暂停：`animator.speed = 0`

架构 §3.1 说「动画用 `Normal` 模式跟随 `Time.timeScale`，无需手动分发」，
但 **D18 决定暂停时 `Time.timeScale` 保持 1**（用 `Physics2D.simulationMode = Script` 停物理）。
**两者一起看：暂停时动画会继续播** ✗ 拼装界面一开，角色还在原地跑跑步机。

**方案**：driver 订阅 `EntityStatus.IsPaused`，暂停时 `animator.speed = 0`、恢复设回 1 ✓

> ⚠️ **敌人的 Animator 也要同样处理** —— 这条要同步给 P1（时间管理器）和 P4。

## 十、攻击（下一步）：**命中窗口由代码拥有**

攻击有 起手 / 生效 / 收招 三段，命中判定只在「生效」段开窗。

| 做法 | 评价 |
| --- | --- |
| Animation Event 在剪辑时间轴上开/关判定 | ❌ 事件挂在**剪辑时间轴**上——快照恢复、变速、动画被中断时都难保确定性；美术剪掉一帧就可能悄悄打乱判定 |
| **代码拥有窗口**（建议）：`_attackWindup` / `_attackActive` / `_attackRecover` 三个序列化秒数，`FixedUpdate` 里按计时开窗 | ✅ 完全可预测、可快照、可单测；动画**只负责看起来对** |

判定窗口与动画时间轴**解耦**，美术调节奏不用改数值 ✓

## 十二、Python 工具（做过的两件事，可复用）

**裁切 + 算轴心**（每个序列取并集包围盒，所有帧裁到同一矩形）：

```python
from PIL import Image
import os, glob
L=T=10**9; R=B=-1; sx=sw=0.0
ims=[(f, Image.open(f).convert('RGBA')) for f in sorted(glob.glob('Idle/*.png'))]
for f,im in ims:
    bb = im.getchannel('A').getbbox()
    L=min(L,bb[0]); T=min(T,bb[1]); R=max(R,bb[2]); B=max(B,bb[3])
for f,im in ims:                       # alpha 质心 → 轴心 x
    a = im.getchannel('A')
    for y in range(im.size[1]):
        for x,v in enumerate(a.crop((0,y,im.size[0],y+1)).getdata()):
            if v: sx += x*v; sw += v
box=(L,T,R,B)
for f,im in ims: im.crop(box).save(f)  # 同一矩形，保住帧间位移
nx = (sx/sw - L) / (R-L)               # → spritePivot.x，y 恒为 0
```

## 十四、攻击范围剑气（2026-10-17）

`PlayerController.OnAttackStruck` 在轻击/重击的实际判定开窗时广播 `PlayerAttackCue`，携带与 `CombatSystem.PerformAttack` 相同的世界中心、尺寸，以及出手朝向、连段序号和轻重击类型。空挥也播放；剑气不负责伤害，不增加射程或重复命中。

`PlayerAnimationDriver.Awake` 自动给同一玩家接入 `PlayerAttackVfx`，已有场景和动态创建的玩家不需要重新挂接。按用户的《空洞骑士》斩击方向，采用亮白实心月牙、尖端拖笔、内缘留白与短残影，命中帧亮起后沿挥斩方向快速擦除；连段交替纵向镜像，重击使用更厚的月牙。月牙外透明，不铺矩形能量底色。组件 Inspector 可调颜色、轻击寿命（默认 0.14 秒）和重击寿命（默认 0.20 秒）。范围直接取控制器的 `_attackBoxSize/_attackOffset` 或 `_heavyBoxSize/_heavyBoxOffset`，不另设特效范围。

剑气在出手位置消退，不随角色位移延伸。每个玩家最多三个复用渲染槽位，无逐刀材质实例或碰撞体。全局/实体暂停冻结，死亡、停用及快照恢复清理；销毁玩家时释放网格和渲染对象。`Data/Resources/PlayerSwordWave_Mat.mat` 显式引用 `PlayerSwordWave.shader`，随 Player 构建保留。

补充光效：每个刀光槽位复用一个外沿冷白辉光层，白色刀刃仍沿用原判定尺寸。核心输出 HDR，已有 Bloom 可响应；独立辉光层保证未启用后处理时也能显示。`SwordLightPulse` 复用一盏 Point Light2D，使用 Renderer2D 的 Multiply 混合以保留纹理颜色。Lit 精灵接收真实补光和已有 ShadowCaster2D 的阴影，当前 Unlit 角色/地面用精灵 alpha 轮廓内的加法反光兼容（最多十二个槽位，出手时只查附近碰撞体）。原本完全无灯的场景仅在脉冲期间补回等价白色环境基底，避免第一盏局部灯导致其他 Lit 精灵突然变黑；已有灯光布局不覆盖。该反光本身不计算遮挡，不自动增加场景阴影遮挡物。

Inspector 新增辉光强度（默认 0.65）、补光强度（0.9）与半径倍率（1.25）；重击补光增强至 1.35 倍。强度设零可分别关闭。补光与剑气一起暂停/清理，单体暂停时反光仍跟随其他实体最新精灵、翻面与位置。原角色和地面共享材质不被替换；没有修改全局 Volume、相机后处理或场景资产。
