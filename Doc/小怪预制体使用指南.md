# 小怪预制体使用指南

适用于 `Assets/_Project/Prefabs/Enemies/FieldMinions/` 下的常用关卡小怪。新增迪斯科球与陀螺的说明见 [专项指南](迪斯科球与陀螺接入.md)。以下资源路径均以 Unity 工程 `Project-Rule/` 为根目录。

## 直接放进关卡

1. 打开已有玩家、规则系统和地面的可玩关卡。
2. 从上述文件夹拖一个小怪预制体到场景。地面怪的脚放在地面上方，玩具鸟放到希望巡飞的高度。预制体中心是身体中心，地面怪的中心高度约为「地面高度 + 身体高度的一半 + 0.05」。
3. 按 Play。小怪会自动找场景中的 `PlayerController`，自动复用本场景的 `CombatSystem`，在自己的范围内巡逻、发现玩家并战斗。

**日常摆怪不需要填写 Target、Combat、ArenaX 或 ArenaY。** 玩家稍后生成也能绑定；自动绑定的旧玩家被停用或销毁后，会继续寻找新实例。缺少目标时每 0.5 秒重试一次，不逐帧遍历场景。当前按单玩家关卡设计，不需要给玩家额外设置 Tag。

每种预制体已包含身体碰撞体、刚体、敌人逻辑、规则响应、独立受击箱及对应表现。受击箱位于 `Hurtbox` 子物体，大小与身体对齐；复制小怪实例即可继续摆放。

## 调整活动范围

选中小怪，在 `EnemyActor` 的简化面板中使用以下选项：

| 选项 | 用法 |
| --- | --- |
| 敌人配置 | 已指定对应类型的配置资产，普通摆放不用改 |
| 以放置点设置活动范围 | 九种预制体默认开启 |
| 活动范围宽高 | 默认 `20 × 20`，单位为 Unity 世界单位；通常只需缩小房间内的范围 |
| 范围中心偏移 | 相对出生位置移动范围中心；默认 `(0, 0)` |

开启 Scene 视图的 Gizmos，选中小怪即可看到黄色矩形；可以直接拖拽边框调整宽高和偏移，也可以在面板输入数字。放到地图任何位置，范围都会以新的放置点为基准，**不会再被世界原点附近的默认边界拽回去**。

范围在运行开始时固定，不会跟着追击中的小怪移动。请在进入 Play 前调整；实例设置只影响这一只，修改预制体则影响未覆盖该设置的所有实例。多选时也可以在面板统一修改范围。

黄色框限制移动和寻路，实际活动还受出生点追击距离限制。范围内必须有实际可达的地面与净空；矩形本身不会创建地形或空气平台。飞行怪同样用这个矩形限制巡飞高度。

需要兼容旧的世界坐标配置时，可以关闭「以放置点设置活动范围」，面板会显示左右、上下边界。原有 Boss 默认保持这一手动模式；本次不会重置 Boss 的场地配置。

## 调整索敌与追击

点击面板中的「敌人配置」，即可在中文配置面板修改索敌、追击、巡逻和攻击等参数。

| 参数 | 默认行为 |
| --- | --- |
| 索敌范围 | 普通小怪 `6`；发条鼠 `3`，玩具鸟 `8` |
| 出生点追击范围 | `8`，以出生位置为中心；超出后停止索敌和追逐，抱抱熊仍可对无遮挡的贴身玩家发起拥抱 |
| 目标记忆 | `1.5` 秒，只记最后看见的位置，不隔墙实时追踪 |
| 巡逻距离 | 大多为 `3`，发条炸弹为 `1.5` |

自动取得玩家引用，不等于立刻发现玩家。玩家仍需进入索敌范围、出生点追击圈并满足视线条件。丢失目标后，小怪先搜索最后已知位置，记忆到期就返回出生点并恢复自己的巡逻或待机；不会靠脱战回满血。

已开始的有限攻击和正在进行的跳跃会先收尾。索敌范围、黄色活动矩形和出生点追击圈是同时生效的限制；只扩大黄色框不会让小怪无限追人。

**配置资产是共享的。** 修改某个 `*_Definition.asset` 会影响引用它的所有实例。要做一只特别强、特别敏锐的小怪，先复制该配置资产，再把副本指定给这只实例。

## 场景只需要准备一次的基础设施

在已有可玩关卡里通常已经具备以下内容，每放一只怪都不用重新添加：

- 玩家带 `PlayerController`，并保留现有玩家生命、攻击和 `Hurtbox` 配置。
- 规则启动器 `RuleSystemDriver` 已配置规则目录，负责场景级规则、时间和世界注册初始化。
- 地面与墙体有 `Collider2D`，使用项目的 `Ground` 层；项目现有 `Enemy` 和 `Hurtbox` 层保持不变。

`CombatSystem` 是共享的命中判定和伤害结算入口，会继续处理伤害反转、挂账等规则。小怪优先复用本场景已有的服务；如果场景没有，会创建一个名为 `EnemyCombatService` 的场景对象供小怪共享。它不是每只怪都要手动指定的组件。

**拖小怪不会替一个空白场景创建玩家、相机、关卡地形或规则目录。** 从现有可玩场景继续制作即可；需要从白盒开始时，打开 `Assets/_Project/Scenes/MinionLabs/Test_Minion_<类型>.unity`。平台寻路示例为同目录的 `Test_Minion_Pathfinding.unity`。

## 常见情况

| 情况 | 先检查什么 |
| --- | --- |
| 小怪没追人 | 玩家是否进入索敌范围与出生点追击圈，之间是否被墙挡住 |
| 小怪走到一半返回 | 玩家离开追击圈，或失去视线超过记忆时间，属于正常脱战 |
| 跳不过去或停在平台边缘 | 目标平台是否可达、落差是否安全、头顶能否容纳整个身体；不是所有敌人都有同样的跳跃能力 |
| 小怪能动但无法打中 | 检查实例是否误删或关闭了 `Hurtbox` 子物体、玩家是否也保留受击箱；不要把身体碰撞体改成受击箱 |
| 多种实例参数一起变了 | 修改了共享配置资产；需要个体差异时复制配置后重新指定 |
| 出现缺少 EnemyDefinition 提示 | 把对应类型的配置资产重新指定给「敌人配置」 |

预制体已补齐本次配置。今后若需要修复旧副本，可使用菜单 `RuleGame > Enemies > 补齐九种小怪的放置配置（保留战斗参数）`；它处理上述九种预制体，开启出生点相对范围、补充缺失的身体受击箱，不覆盖生命、伤害或现有表现参数，重复运行不会增加重复受击箱。自定义的场景实例受击箱应保留一个本体判定框，避免与新增的预制体子物体重复。

## 抱熊交战坐姿与小鸟升降修正

抱熊原本把交战中站定映射到 Idle，而交付 Idle 是坐姿；通用破韧恢复又回到 FirstAction=Idle，导致打斗中突然坐下再站起。新增 Ready 接线，直接复用 Stand 最后一帧，不增加原图；交战停位、拥抱冷却均保持站姿，受击后根据交战状态恢复追击或回位，仅脱战回到出生点才进入 Sit。坐下过程中发现目标会重新站起；站立标记随快照恢复。

## 同日抱抱熊首次接近不攻击修复

## 规则接入核对（2026-10-20）

以下为本轮实装前的缺口记录；已在下节补齐。静态核对 12 个现有非 Boss 敌人预制体（10 个 FieldMinions，加 BrickMinion/BatMinion），均含 RuleAffectedBody，摩擦/质量响应开关开启；EnemyMotor 读取规则重力、摩擦和质量，自定义攻击统一走 CombatSystem/DamageProcessor，Actor 参与快照恢复。该结论是公共接线核对，不是逐怪逐规则验收。蜘蛛、陀螺、迪斯科球未实现，未纳入。

已确认的具体缺口：

- 时间失效：矩阵要求冷却等时间机制失效且动画照常；通用 EnemyBrain 与小怪技能冷却仍推进 Age/ReadyAt，没有读取 TimeMechanicsEnabled。时钟 Boss 的特例不能代表所有小怪。
- 摩擦增强：EnemyMotor 当前放大加速度，目标移速仍为 MoveSpeed × SpeedMultiplier，未实现矩阵描述的沼泽式降速。
- 摩擦反转：FieldMinionBrain 的 FleeMode 把除 Attack 外的动作统一改为 Chase 并提前返回，会跳过熊的 Hug、海豹技能、小鸟高度控制等专属行为；而 Motor 仅接地时反转横向意图，飞行怪不能直接套用这一地面逃离处理。

这些是本轮代码核对发现，未做完整的六属性×五关系×全部小怪运行验收；本轮未修改规则系统或上述适配逻辑，投掷物继续按用户要求保持现状。

## 规则完整接入与拖放交付（2026-10-20）

范围为当前已有的 12 个非 Boss 小怪预制体：10 个 FieldMinions，加 BrickMinion 和 BatMinion。蜘蛛、陀螺、迪斯科球仍不新增玩法；投掷物代码、资源与尺寸不改。

在已有可玩地图里，直接拖放即可：地面怪脚部放到地面，小鸟放到巡飞高度。玩家、战斗服务、规则注册与受击箱均自动接线，活动范围按放置点建立；玩家稍后生成或被新实例替换也能自动绑定。空白场景仍需地图自身的玩家、地形和 RuleSystemDriver。两种原先只用于 Boss 召唤的小兵也开启出生点相对范围；由 Boss 实际召唤时继续继承 Boss 场地，不覆盖父边界。EnemyLabBuilder 同步生成默认值。

| 属性 | 本轮交付行为 |
| --- | --- |
| 重力 | 所有实体读取世界重力。跳跃使用正常重力下的固定起跳速度，增强时跳低、削弱时跳高，导航弧线与实际运动共用参数。点燃引信或拥抱只锁自主移动，世界重力和外部冲量继续生效。飞行实体沿用重力差值漂移。 |
| 时间 | 分开动作时钟与机制时钟。失效时暂停技能/施法冷却、引信、周期接触/拥抱伤害、持续控制与重组计时，动画及普通移动继续；取消后接续剩余时间。机制时钟和冲撞间隔随快照恢复。变速与恒定/反转继续走公共时间和世界快照。 |
| 摩擦 | 增强降低接地目标移速，削弱降低加减速；失效不能凭普通行走起步，已有动量继续滑行，普通收步不能瞬间吃掉冰面动量。反转仅改变接地运动，不再把所有专属动作强改为 Chase，飞行保留高度控制。 |
| 质量 | 规则更新刚体质量，真实加速度、击退和导航预测一致，质量取倒数覆盖轻重两侧，规则期间生成的新实体也立即生效。 |
| 伤害/生命 | 继续走共享 DamageProcessor：倍率、攻击/治疗反转、失效及净额挂账结算。 |
| 因果 | 继续处理对象反转、随机与扩散；补齐失效时的全体治疗和跨阵营回能共享。玩家命中、敌人命中及敌人自然回能走同一恢复入口；规则结束后恢复各自回能。敌人共享命中回能由 EnergyPerHit 配置，默认沿用玩家基础值 4，仅在因果恢复共享时触发。 |

为让恢复共享与世界回溯覆盖测试玩家，PlayerController 自动补齐缺失的 RuleAffectedBody；无需策划逐场景手动添加。所有计时仍服从原有暂停入口，不使用停止动画来代替时间失效。

## 全部现有敌人 AI 强化（2026-10-20）

本轮在当前 main 上覆盖 12 种已有非 Boss 敌人及 4 个 Boss，只调整已有行为的选择、追击、瞄准和恢复，不提高生命/伤害数值、不增加技能或怪物。预制体继续直接拖放；投掷物脚本、资源、尺寸和弹池不变。

| 对象 | 强化后的行为 |
| --- | --- |
| 通用追击与瞄准 | 读取玩家实际移动速度（包括 Kinematic Slide），向移动方向预判；预判点遇地形截断。失去视线仍只搜索最后已知位置，死亡玩家不再作为有效目标。 |
| 石头人、积木士兵 | 冷却期继续压近；攻击按原配置冷却恢复，不额外叠加一整段无视等待。保留攻击前摇和至少短暂恢复。 |
| 积木小兵、蝙蝠小兵 | 追逐可见目标并预判接近位置；蝙蝠召唤物看到玩家即主动接敌，不必一直等待 Boss 命令。 |
| 自爆方块、发条炸弹、冲撞方块 | 方块巡进时朝向可见目标，炸弹沿共用追击路径逼近，冲撞方块采用预判接近；身体阻挡与地形阻挡分开判断。 |
| 弹簧怪、发条鼠 | 根据目标高度选择现有高低跳；鼠从当前位置判断钻出方向，被挡住时钻地重整，避免一直顶墙抖动。 |
| 玩具鸟 | 上下追击参考目标预判高度；保留立体巡飞、射程滞回、早期修正瞄准及随后锁向。 |
| 抱抱熊 | 保留接触优先拥抱、站立冷却和攻击挣脱；拥抱冷却时看到近身攻击，延迟 0.15 秒后尝试短暂后撤，受地形/悬崖和原有拥抱冷却限制，计时可回溯。 |
| 海豹 | 近身/同高度优先滑撞，远处或高处优先拍肚落冰；三种现有技能各自沿用技能间隔冷却，技能间保留 0.25–0.6 秒恢复。冷却中调整站位；嚎叫仍为规则施法，仅在规则有实际变化且可支付能量时使用，不机械开场嚎叫或重复相同规则。滑行保留完整蓄势、锁向和接触命中。 |
| 积木 Boss | 前压遇地形及时选招，出招时停步；锤击/投掷前摇早段修正朝向，之后锁定，有限连招及休息保留。 |
| 发条 Boss | 乱跑起手前摇早段选择方向，之后锁定；完整乱跑、撞墙折返、独立指针激光及休息保留。 |
| 兔子 Boss | 开场就能使用已有近身撤退，之后沿用撤退冷却；被场地边界卡住时及时使用可用投掷，避免无效等候。 |
| 蝙蝠 Boss | 第二阶段的召唤、命令和规则施法不再被冲刺持续抢占；靠近、俯冲起手和现有弹幕使用实际移动预判，保留原有预警、锁向和休息。 |

同时修复接触伤害漏洞：玩家身体会先挡住敌人，而玩家受击箱比身体略小，原逻辑要求敌人进一步穿入受击箱，导致积木小兵、蝙蝠小兵和发条鼠实际贴身也不掉血。现在将确实接触的身体关联到仍启用的正规 Hurtbox，继续经过公共阵营过滤、去重、伤害规则和接触冷却；关闭受击箱或隔着薄墙都不能命中。

新增 `EnemyAiValidation.RunBatch`：16 类敌人逐一验证真实玩家移动预判、15 秒物理对战、死亡目标与快照，另查海豹选招/技能衔接、熊的反应后撤、前摇锁向、召唤物主动接敌及接触伤害边界。第一轮旧实现 45 组失败，修改后通过；物理对战补查发现接触伤害漏洞，修复后最终 63 组通过。

旧测试核对：HEAD 的 `FieldMinionValidation` 同样有 6 项失败，根因为测试玩家没有正规 Hurtbox、使用旧动作时长、假设鸟只水平飞或海豹机械轮招。已补齐测试受击箱（含同一玩家多箱去重），按实际动画命中点测试，并按新选招语义校验；未修改生产伤害数值迎合测试。`MinionDecisionValidation` 的海豹用例改为等待真实滑行及进入实际拍肚状态，再严格检查动作帧。`BossCombatValidation` 保留破韧阈值而不要求轻击必硬直；发条攻击按真实 Charge 状态和独立技能冷却判定，不要求不存在的挥击反馈。兔子开场撤退旧失败由本轮行为修复。
