## 0. 一条贯穿全篇的原则

**动作只改「玩家自己怎么动」，不替世界做判断。**

- 改变的是**发起方自己的速度**，不是别的实体。想动世界，那是「规则」的事。
- **免疫、抗性之类的特例不进动作代码**（约束 C4）—— 挡不挡得住是承受方自己的事。
- 每个能力都是**序列化字段**，描述的是**这个实体的能力**，不是「玩家的特权」。
  敌人控制器想要二段跳 / 冲刺 / 蹬墙，配置一下就有。

> ⚠️ **待团队确认的设计张力**：项目基调是「玩家受与 NPC 相同的物理约束，唯一特权是拼规则」。
> 多段跳 / 冲刺 / 蹬墙跳都是**额外的机动能力**，与该基调有张力。
> 目前处置是：把它们当**实体能力**（可序列化、谁都能配）。
> 若要收得更紧，可以改成「被规则解锁」——把段数 / 次数接到规则读值即可。

## 1. 移动

水平方向**给加速度**，而不是瞬间到最大速度；松开方向后按地面材质减速，反向输入时先制动到零再加速反向。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_moveSpeedMax` | 8 | 水平最大速度 |
| `_groundAccel` | 200 | 地面加速度（到全速约 0.04 秒，近乎瞬时） |
| `_lowFrictionGroundAccel` | 40 | **低摩擦地面（冰面）**上的地面加速度。按抓地系数与 `_groundAccel` 插值 |
| `_airAccel` | 40 | 空中加速度。0 = 空中完全锁死横向速度 |
| `_airDrag` | 3 | 空中无输入时的水平阻力。0 = 完整保持动量 |
| `_frictionDecel` | 40 | 地面减速基准 |
| `MinimumTurnBrakeDecel` | 12 | 接地反向输入时的最低制动加速度 |

- **减速按材质**：松开输入时 `实际减速 = _frictionDecel × 脚下地面的摩擦系数 × 摩擦规则缩放`。
  地形做成冰面 = 给地面挂一个摩擦很小的 `PhysicsMaterial2D`（或铺 `SurfaceTile` 瓦片）。
- **加速也按材质**：`实际加速` 按抓地系数 `grip = 地形摩擦 × 摩擦规则缩放`（「× 加强」时补一份，
  把冰面拉回普通地面）在 `_lowFrictionGroundAccel`（`grip = 0`，完全打滑）与 `_groundAccel`（`grip = 1`）
  之间线性插值。不这么做的话冰面上「一按就满速、松开滑很久」，起步和刹车的手感对不上。
  「摩擦 × 减弱」因此也会让普通地面的起步变迟缓 —— 同一个 `grip` 同时管加速与减速。
- **反向输入先制动**：输入方向与当前水平速度相反时，先向 0 制动，制动值为
  `max(_frictionDecel × 脚下地面的摩擦系数, MinimumTurnBrakeDecel) × 摩擦规则缩放`；速度过零后才按 `_groundAccel` 加速到新方向。
  `Ice2D` 摩擦系数为 0.05，最低制动值为 12 时，从 8 降到 0 约需 0.67 秒。
- **摩擦 × 反转**：接地且有方向输入时，移动方向取反（按右往左走）。
  只作用于接地 —— 语义是「摩擦力的方向」，空中没有摩擦。
  反转**不翻减速的符号**（减速力反向会变成越滑越快，直接失控）。
- 判据抽成纯函数 `ResolveMoveDirection(rawInput, frictionInverted)`。

## 2. 跳跃

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_jumpSpeed` | 13.6 | 起跳速度。高度 = `v² / (2 × 有效上升重力)` |
| `_gravityScale` | 3.83 | 玩家自身重力倍率（叠在规则改过的全局重力之上）|
| `_fallGravityMultiplier` | 2 | 下落额外重力，落得比升得快 |
| `_maxFallSpeed` | 30 | 终端速度 |
| `_jumpCutMultiplier` | 0.45 | 松键削速（可变跳跃高度）|
| `_coyoteTime` | 0.1 | 走出平台后仍可起跳的宽限 |
| `_jumpBuffer` | 0.12 | 落地前提前按也算数 |

### 2.1 多段跳

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_maxAirJumps` | 1 | 空中还能再跳几次。0 = 只有一段跳 |
| `_airJumpSpeed` | 12.2 | 空中段速度。比第一段略弱，读起来像「再补一下」 |

**跳数模型**：`_jumpsUsed` 计数，接地归零；空中另有两条规则：

```
接地            → _jumpsUsed = 0
空中 · 土狼窗口内 → 第一段 + 空中段都还在（与站着跳等价）
空中 · 窗口关闭   → _jumpsUsed 至少为 1（第一段视为已用掉）
```

| 情形 | 可用跳数 | 第一段速度 |
| --- | --- | --- |
| 站着跳 | 2 | 13.6 |
| **走进**土狼窗口内跳 | 2 | 13.6 |
| 走出窗口后再跳 | 1 | 12.2（只剩空中段）|
| 单段跳角色走出窗口 | 0 | — |

> ⚠️ **为什么「走出窗口 = 第一段已用掉」**：若走下来不消耗第一段，第一段在空中的判据就只能是
> 「窗口内」，那窗口一过玩家会**一段跳都没有**——比现在更差。
> 要更宽容就调大 `_coyoteTime`，不要改这个模型。

### 2.2 起跳优先级（重要）

**地面 / 土狼跳  >  蹬墙跳  >  空中跳**

> ⚠️ 蹬墙必须排在**空中跳之前**：否则贴着墙、跳数还没用完时，空中跳会抢先把这一下吃掉，
> 玩家得先把二段跳耗完才蹬得上墙 —— 反直觉。

判据抽成纯函数 `ResolveJumpSpeed(...)`（返回 0 = 这一段用不了）。

## 3. 冲刺

### 3.1 意图

给玩家一段**瞬间的高速水平位移**：跨缺口、穿危险区、在规则把世界搞乱时保持可控。

### 3.2 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_dashSpeed` | 26 | 冲刺水平速度。远高于 `_moveSpeedMax = 8`，要的就是爆发感 |
| `_dashDuration` | 0.18 | 持续秒数 → 距离 ≈ `26 × 0.18 ≈ 4.7` 米 |
| `_dashExitSpeedScale` | 0.35 | 结束时**水平**速度保留多少 |
| `_maxDashes` | 1 | 落地回满的冲刺次数 |
| `_dashCooldown` | 0.25 | 两次冲刺之间的最小间隔 |

### 3.3 状态机

```
CanDash = (_dashesLeft > 0) && (_dashLeft <= 0) && (_dashCooldownLeft <= 0)
```

| 时刻 | 行为 |
| --- | --- |
| 按下且 CanDash | `_dashLeft = _dashDuration`；`_dashDirection` = 左右；`_dashesLeft--` |
| 冲刺中每物理帧 | **只**把 `_velocity.x` 设成 `_dashDirection.x × _dashSpeed` |
| 冲刺结束 | `_velocity.x ×= _dashExitSpeedScale`，开始冷却 |
| 接地 | `_dashesLeft = _maxDashes` |
| 每帧 | 冷却推进（地面空中都走）|

### 3.4 ⚠️ 冲刺只管水平：竖直速度**原样保留**

**这是冲刺最容易被改坏的地方 —— 已经改坏过一次。**

| 轴 | 冲刺期间 |
| --- | --- |
| 水平 | **被冲刺完全接管**：不读方向键、不受摩擦影响 |
| 竖直 | **重力不积分，竖直速度原样保留**（不归零、也不加速）|

- **冲刺方向只有左右两向**（`ResolveDashDirection` 返回 `(±1, 0)`）。
  斜向输入只取水平分量，竖直分量直接丢掉 —— 冲刺不做「八向冲刺」。
- **冲刺期间不积分重力**。曾经试过让重力照常作用，结果是：空中冲刺时又叠一份下落加速度，
  轨迹变成一条又陡又快的斜线，**非常突兀**。停掉积分后，起跳途中冲刺会继续上升、
  下落途中冲刺保持当前下落速度 —— 冲刺**既不给你加竖直速度，也不拿走你的**。
- 冲刺在「重力被规则搞乱」时依然可预测：横向照常给力，纵向交回给世界。
- 📌 **别再改成「冲刺期间照常跑重力」**。若还想更接近「悬浮」，下一步是在冲刺开始时
  把竖直速度**清零**（那才是动了竖直方向的大小，要先确认再改）。

**输入**：冲刺期间**不读方向键**，但**跳跃整块跳过**（`if (!IsDashing)`）——
于是冲刺中按下的跳跃会被留到冲刺结束那一刻兑现（跳跃缓冲够长就衔接得上）。

### 3.5 与规则系统的交互

| 规则 | 冲刺时的行为 | 理由 |
| --- | --- | --- |
| 重力 × 任意 | **冲刺期间不生效**（竖直速度保留）；结束后立刻恢复当前生效的重力 | 不叠加下落加速度，空中冲刺才不至于又陡又快 |
| 摩擦 × 缩放 | 冲刺中不受摩擦减速 | 水平速度被冲刺接管，摩擦没有作用点 |
| 摩擦 × 反转 | **不翻**冲刺方向 | 反转改的是「地面给的力」，冲刺不是地面给的。与跳跃同理 |
| 质量 × 任意 | 不受影响 | 质量影响的是**外力 / 撞击**，主动位移不吃它。物理上自洽 |
| 伤害 × 任意 | 无交互 | 冲刺不给无敌帧（那是承受方的事，约束 C4）|

> ⚠️ **冲刺不给无敌帧**。想「冲刺穿弹幕」得靠别的机制（未来可由因果 / 伤害规则实现），
> 不要偷偷在冲刺里塞免疫 —— 那违反约束 C4。

### 3.6 输入

⚠️ **临时决定，等输入方案定稿再改**：复用输入资源里**未被任何代码使用**的
`Player/Crouch`（**C 键** / 手柄 buttonEast）作为冲刺键。

- 好处：**不动团队共享的 `InputSystem_Actions.inputactions`**，避免和队友产生资源冲突。
- 代价：动作名是 `Crouch` 而语义是冲刺，读代码会愣一下。
- 📌 最初用的是 `Player/Sprint`（左 Shift），后来按团队意见换成了 `Crouch` ——
  Shift 在很多编辑器 / 输入法里有系统级占用，C 更干净。
- **要改的话**：在输入资源里把 `Crouch` 重命名成 `Dash`
  （或新增 `Dash` + `<Keyboard>/c` + `<Gamepad>/buttonEast`），
  然后改 `PlayerController.Awake` 里那一行 `FindAction("Player/Crouch")`。

> 没用过的候选还有 `Look` / `Previous` / `Next` / `Interact`。
> 其中 **`Interact` 留给道具系统**（`Player/Interact` = E 键），别占用。

## 4. 贴墙下滑 & 蹬墙跳

### 4.1 意图

让玩家能**顺着竖井左右互蹬爬上去**。为此需要两件事配合：

1. **贴墙缓慢下滑** —— 给你时间看清下一步，而不是一贴到墙就嗖地掉下去；
2. **蹬墙跳** —— 朝墙外弹开 + 向上，这样才接得住对面的墙。

### 4.2 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_wallProbeDistance` | 0.08 | 横向墙面探测距离（米）|
| `_wallSlideSpeed` | 6 | 贴墙时的下滑速度上限。远低于 `_maxFallSpeed = 30`（约 1/5）|
| `_wallJumpUpSpeed` | 15 | 蹬墙后的向上速度。**调大它是最划算的提升** |
| `_wallJumpPushSpeed` | 9 | **朝墙外**按时的推力 —— 「跳出去」用 |
| `_wallClimbPushSpeed` | 4 | **朝墙**按 / 不按时的推力 —— 「爬升」用，**必须小** |

### 4.3 贴墙下滑

```
空中  +  贴着竖墙   →   下落速度被压到 _wallSlideSpeed
```

- ⚠️ **这不是「吸附」**：人**照样在往下掉**，只是掉得慢（6 比 30，约 1/5）。
  离开墙或落地**立刻**恢复正常下落。它给的是**时间**，不是把角色挂住。
- **不需要按方向键**，贴到墙就下滑。若要改成「必须朝墙按住才下滑」，
  在 `FixedUpdate` 的 ④′ 加一个朝向判断即可。
- 冲刺期间不生效（冲刺本来就不积分重力）。
- 📌 调大 = 贴墙停留时间短、掉得快；调小 = 有更多时间看准再蹬。

### 4.4 蹬墙跳：两档推力

```
贴竖墙  +  按跳  +  没踩在地上   →   朝墙外弹开 + 向上
```

**关键：推力分两档，由「方向键是否朝着墙外」决定。**

| 输入 | 推力 | 结果 |
| --- | --- | --- |
| 墙在右、按**左**（朝墙外）| `_wallJumpPushSpeed`（9）| 往**左**蹬出去，够跨到对面墙 |
| 墙在左、按**右**（朝墙外）| `_wallJumpPushSpeed`（9）| 往**右**蹬出去 |
| 墙在右、按右 / 不按 | `_wallClimbPushSpeed`（4）| 仍然往左弹，但**只弹一点点** |
| 踩在地上 | — | 不蹬，按普通地面跳处理 |

- ⭐ **为什么要分两档**：**一面墙就能一路爬上去**。你按着朝墙的方向，空中加速度
  （`_airAccel`）会把你往回拉；推力只要够小，人还没离开墙就被拉回去了 ——
  于是「贴墙 → 跳 → 贴回去 → 跳」可以无限续下去。**推力一大，人会被推飞、接不上**，
  变成越跳越远。而竖井里又确实需要足够的横向速度跨到对面墙，所以留了大的那一档。
- **效果**：`_velocity = (推力, 0)` 再把「上」分量设成 `_wallJumpUpSpeed`，
  **并且 `_jumpsUsed` 归零** —— 蹬墙刷新跳数，所以能无限次连续蹬。

判据抽成纯函数 `ResolveWallJumpPush(...)`，**返回带符号的水平速度**（0 = 不能蹬）。

#### 想要「一次跳得更远」时调哪个

**优先调 `_wallJumpUpSpeed`**（向上速度）。蹬得更高 → 滞空更久 → **水平距离跟着白拿**，
而且弧线更漂亮。单纯加水平推力只会让弧线变平、同时把爬升档也推飞。
（《空洞骑士》的蹬墙跳质感就来自「够高 + 够远」，不是只靠水平速度。）

实测（默认 9 / 4 / 15）：从右壁朝外蹬，`v = (-9.00, 15.00)`，
**一路飞过 4.4 宽的竖井撞到对面左壁** —— 单跳就够跨井。

### 4.5 ⚠️ 墙面探测的两个坑（都踩过）

1. **`Rigidbody2D.Cast` 在形状已经接触某碰撞体时，会把它当成 `distance = 0` 的命中返回，
   不管你朝哪个方向扫。** 于是贴着**右**墙时「朝左扫」也会命中那面右墙 ——
   不判方向的话两侧都报「有墙」，蹬墙方向就会错。判据：法线要**顶着**扫描方向
   （`dot(normal, direction) < -0.5`）。
2. **只认竖墙**：法线要基本垂直于「上」（`|dot(normal, _up)| <= 0.5`）。
   否则站在地上也会被判成「贴着墙」。

方向用**世界坐标的左右**，不用 `_up` 推出来的「左右」：重力反转翻的是上下，不翻左右。

### 4.6 尚未做的

- **蹬墙没有锁定期**：蹬出去之后立刻回头贴同一面墙还能再蹬。竖井里这是正常玩法，
  不是 bug；若觉得能原地刷，再加一个短锁定。
- **贴墙下滑没有专门的表现**（粒子 / 摩擦声）—— 等美术定了再说。

## 5. 与「暂停」的关系

暂停期间：不读输入、速度清零、冲刺计时与冷却**冻结**。
冻结由 `EntityStatus.SetPaused` 显式驱动（策划案 §3.1 禁止用 `Time.timeScale = 0`）。

实现上冲刺计时用 `Time.fixedDeltaTime`，而 `FixedUpdate` 在暂停时**提前 return**，
所以计时天然冻结 —— 不需要额外的暂停分支。

## 6. 每个物理帧的处理顺序

改 `FixedUpdate` 前先看这个顺序，它决定了各种状态谁覆盖谁：

```
① 接地探测（地面 + 左墙 + 右墙）
①′ 风场探测                  —— 我在哪个风场里、受多少力；**力 ÷ 质量** 得加速度（§9）
② 跳数 / 土狼时间维护        —— 与冲刺无关，一直推进
③ 冲刺计时 / 次数 / 冷却      （UpdateDash）
④ 重力 + 终端速度 + 风场竖直分量与空气阻力
                             —— 冲刺期间**都不积分**（竖直速度原样保留）
④′ 贴墙下滑                  —— 空中贴墙时把下落速度压到 _wallSlideSpeed
                             （竖直轴归墙独占，风也被挡在这条之外）
⑤ 水平：冲刺接管 → 否则接地/空中逻辑
⑤′ 风的水平分量 + 空气阻力
⑥ 贴地时抵消朝地面累积的速度
⑥′ 弹簧发射                  —— 脚下的面在回弹时把它给的速度写进竖直速度（§8）
⑦ 跳跃（冲刺期间整块跳过）    —— 缓冲 → 地面跳 > 蹬墙跳 > 空中跳 → 松键削速
⑧ 击退衰减
⑧′ 承载                      —— 脚下是会动的支撑面时把它的速度并进来（§7）
⑨ Rigidbody2D.Slide 解算接触
⑩ 撞墙 / 撞顶：清掉用不掉的速度分量
```

## 7. 移动平台承载

站在**会动的支撑面**上时要跟着它走 —— 否则平台一挪开，人就原地悬空。

### 7.1 为什么得自己写

玩家是 Kinematic 刚体，位移由 `Rigidbody2D.Slide` 自己解算（内部走 `MovePosition`）。
**引擎不会把「脚下那块地在动」告诉它**：`MovePosition` 对 Kinematic 体就是「搬过去」，
既没有推挤也没有接触回调。所以承载只能是**平台报速度、玩家自己并进位移**。

| 角色 | 做什么 |
| --- | --- |
| `MovingPlatform`（`Gameplay/Scene`） | 实现 `IMovingSurface`，每帧报 `Velocity = 这一步实际走的距离 ÷ dt` |
| `ContactSensor.ProbeGround` | 接地扫到的东西上找 `IMovingSurface`，速度放进 `State.CarrierVelocity` |
| `MotionMover.Move` ⑧′ | `slideVelocity += contact.CarrierVelocity` |

耦合点只有 `IMovingSurface`（`Gameplay/Common`）：**玩家不认识任何具体场景组件**。
滑板车 / 升降台 / 传送带，谁实现它谁就能带人。

### 7.2 三条实现约束

1. **给速度，不给位移。** 并进 `slideVelocity` 再交给 `Slide`，被平台顶着撞墙时才会被正确挡住；
   直接搬位移会穿过墙壁。
2. **绝不写回 `_velocity`。** 平台速度不是玩家自己的速度。写回去有两个后果：
   跳离平台会带着平台的动量继续滑；⑩ 的清零会连玩家自己的速度一起赔掉。
3. **只在接地时读。** 空中擦过不算承载。副作用正好是对的：
   在平台上起跳的那一帧**仍算接地**，于是起跳会带上平台那一帧的水平速度；
   之后脱离支撑面就读不到了，恢复成自己的速度。

> ⚠️ **待拍板**：跳离移动平台**不继承**平台动量（平台会从脚下溜走）。
> 想改成物理上继承的话，在起跳那一帧把 `contact.CarrierVelocity` 加进 `_velocity` 即可。
> 现在的选择是「可控优先」—— 跳出去的弧线与站在平地上一致，好预判。

### 7.3 实测

| 方向 | 平台位移 | 玩家位移 | 相对差 |
| --- | --- | --- | --- |
| 水平（含 1 次折返） | 1.8178 | 1.8178 | **0.000000** |
| 竖直（含 4 次折返） | — | — | **−0.010371，恒定** |

竖直那 −0.01 是**初始落地那一下的固定偏移**（起点有 2cm 缝），前后两次采样到小数点后六位完全一致，
不随时间增长。

「面走多远」与「被带走多远」逐帧严格相等、**不累积漂移**：两边都按 `Time.fixedDeltaTime` 推进，
而平台报的速度正是「本步位移 ÷ dt」。

### 7.4 与暂停

暂停时 `Physics2D.simulationMode = Script`，`MovePosition` 不生效 → 平台静止；
`MovingPlatform` 也把 `Velocity` 置零。承载方读到的就是 0，**不需要额外的暂停分支**。

## 8. 弹簧平台（静力学平衡）

弹簧平台（`SpringPlatform`，`Gameplay/Scene`）压缩到**「重力 = 弹簧力」的平衡位置之后停在那里**，
载重拿掉才回弹到自然长度。它不是「踩一下弹一次」的弹跳板。

### 8.1 三个状态

```
Idle         空载，停在自然长度
Compressing  有载重，往平衡位置走 —— 到了就停住，不自动释放
Releasing    载重消失，回弹到自然长度
```

**目标压缩量 = `载重 ÷ _fullCompressionMass`**（夹在 0 ~ 1），由阻尼弹簧积分趋近。
所以「压多深」直接由重量决定：玩家 1 kg 压到底，更轻的东西停在半路。

### 8.2 承重按质量算，不按层

探测框里**带 `Rigidbody2D` 的东西**都算载重（玩家、铁箱、石头），静态地形没有刚体，压不动它。
同一个物体的多个碰撞体只按刚体算一次。

| 谁压上来 | 质量 | `_fullCompressionMass = 1` 时 |
| --- | --- | --- |
| 玩家 | 1 kg | 压到底 |
| 铁箱 | 8 kg | 压到底（封顶） |
| 铁箱 × 削弱 | 2.4 kg | 压到底（封顶） |
| 铁箱 × 失效 | 0.4 kg | 只压到 40% |
| 玩家 × 削弱 | 0.3 kg | 只压到 30% |

> 没有任何特判：质量规则写的就是 `Rigidbody2D.mass`。把 `_fullCompressionMass` 调到 8，
> 就变成「玩家压不动、得用铁箱才压到底」的机关。

### 8.3 与承载的关系

平台带人走 §7 那一套（`IMovingSurface`）：压下去的时候，站在上面的实体跟着一起下沉。
**不需要**任何额外的「把人顶起来」的机制 —— 位置跟随就够了。

### 8.4 参数（组件上的序列化字段）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_restLength` | 2 | 自然长度：空载时平台中心在锚点上方多高 |
| `_compressedLength` | 0.8 | 压缩长度：压到底时的高度。**两者之差就是行程** |
| `_springConstant` | 90 | 劲度系数 k。越大越硬 —— 走完行程越急。ω = √k，约 π/ω 秒 |
| `_damping` | 12 | 阻尼。临界阻尼 ≈ 2√k（k=90 时约 19）。取一半左右读起来最有弹性 |
| `_fullCompressionMass` | 1 | **压到底需要多少质量**（kg）。载重 = 上方带刚体的东西质量之和 |
| `_friction` | 1.5 | 平台表面摩擦系数。1 = 普通地面，越大越抓地，< 1 像冰面 |

> 摩擦参数落在**每个实例独占的** `PhysicsMaterial2D` 上 —— `sharedMaterial` 是共享的，
> 直接改它会让所有引用同一材质的物体一起变。玩家侧读的就是 `sharedMaterial.friction`，
> 没有材质就一律按 1 算。**摩擦规则不受影响**：它只在外面乘倍率（`GroundFriction × FrictionScale`）。

### 8.5 四条实现约束

1. **没有自动释放。** 只要还有载重就停在平衡位置 —— 早先版本「压到底 → 停一下 → 弹回」
   的状态机与静力学平衡冲突，已删除。
2. **方向恒为世界竖直，锚点的 x 就是平台的 x。** 不要旋转根物体 —— 位姿每帧按锚点解算。
3. **积分必须拆子步。** 半隐式欧拉在 `ω·dt > 2` 时发散（k=5000 → ω≈70，50Hz 下 ω·dt≈1.4）。
   组件按 `ω·h ≤ 0.2` 自动拆。
4. **压缩量夹在 0 ~ 1（硬限位）**：平台不会缩进锚点里，也不会被"顶"过自然长度。

> **弹射相关代码保留但已停用**：`ISpringSurface` 接口与玩家侧的 ⑥′（`LaunchDelta`）
> 仍在代码里，`SpringPlatform` 不再实现它，所以 `LaunchDelta` 永远返回 0。
> 预留给将来的弹跳板 / 蹦床 —— 实现那个接口就会被弹。
> 移除原因：弹簧停在平衡位置时不会自己释放；而「载重消失」的那一刻东西已经离开，没有可弹的对象。

> ⚠️ **不受重力规则影响**：弹簧是 Kinematic，锚点钉在世界固定位置，压缩方向恒为「朝锚点」。
> 重力反转后平台仍然停在那里，只是没人再踩它。

## 9. 风场

风场（`WindZone`，`Gameplay/Scene`）在区域内给实体一个**随高度线性变化**的力。
它撑起的玩法就是核心判据本身：**质量 / 重力规则一改，人在风里浮的高度当场变化** ——
「世界变了」，不是「手不听话了」。

### 9.1 四个角色（与 §7 承载同一个模式）

| 角色 | 做什么 |
| --- | --- |
| `IWindField`（`Gameplay/Common`） | 唯一耦合点：报**力**（牛顿，`ForceAt(point)`）+ 空气阻力（`DragAt(point)`）+ **竖直阻尼**（`VerticalDampingAt(point)`，只收竖直轴） |
| `WindZone`（`Gameplay/Scene`） | Trigger 区域；底部 / 顶部两个力字段，沿世界 y 线性插值 |
| `Fan`（`Gameplay/Scene`） | 风扇：从扇体沿**风向**吹出一条矩形风道，力沿**离出风口的距离**衰减（§9.5） |
| `WindSensor`（`Gameplay/Player`） | 每物理帧 `OverlapPoint` 查自己所在风场，**力 ÷ 质量 → 加速度**（①′） |
| `VelocitySolver` | 竖直分量并入 ④（**与重力同待遇**）、水平分量在 ⑤′、空气阻力在两处都收速度 |

风场**不主动推人** —— 玩家和敌人都是 Kinematic 刚体，引擎的力对它们无效。
这与 §7 / §8 是同一条道理：**谁进谁的场，谁自己读**。

### 9.2 为什么报力、不报加速度

`a = F / m`。风报恒定**力**、由实体自己除以质量：

| 属性 | 规则给世界的作用量 | 质量能不能影响它 |
| --- | --- | --- |
| 重力 | 恒定**加速度**（`Physics2D.gravity`） | 不能 |
| 风场 | 恒定**力** | **能** —— 力不变、质量变，加速度成比例变 |

这是「质量」这条属性规则**产生玩法意义的唯一途径**，也是它目前**唯一的消费方**
（`RuleAffectedBody` 一直在写 `Rigidbody2D.mass`，此前没有任何移动代码读它）。

### 9.3 力必须随高度衰减，而且必须有阻尼

两条都是**实测踩出来的**，不是设计洁癖：

1. **恒定力做不出「停留位置」**。玩家要么一路加速飞出风场，要么减速掉回来 —— 只有阈值，没有平衡点。
   让力随高度**按梯度衰减**（每米减少多少牛顿），才存在 `F(y) = m × g` 那个平衡高度，
   「改质量 / 改重力 → 换一个高度」才成立。梯度填 0 即退化成恒定力。
2. **只有力的平衡还不够 —— 还要有耗散**。从低处进来的玩家带着一路攒下的动能**冲过平衡点**：
   无阻尼实测出场速度 **18 m/s**，飞到场顶再掉回来、周而复始，永远不停。
   加上阻力的第一版实测才出现稳定的浮沉带。
3. **空气阻力是各向同性的，竖直方向仍然欠阻尼**。阻尼比 ≈ 0.26（150N / 10m / 质量 1）——
   玩家还是会绕着平衡高度上下弹好几次。于是另有一个**只作用于竖直轴**的「竖直阻尼」
   （`_verticalDamping`，与空气阻力叠加）：想让人更快停住就调它，横向手感完全不动。
   **「y 方向速度逐渐减少」就是这一项**；把空气阻力调成 0 则只留竖直方向的收速。

> ⚠️ **风场里重力统一为上升重力**（玩家自己 `_fallGravityMultiplier` 的 ×2 **在风场内不生效**）。
> 不统一的话，「上升 ×1、下落 ×2」是**方向依赖（非保守）**的力：每上下一个来回它净做正功
> `(g_落 − g_升) × 行程`，于是在上升 / 下落两个平衡点之间**自激振荡** —— 阻尼再大也只能把振幅压小，
> 消不掉（实测：150N + 阻尼 8 能停，200N + 阻尼 8 就一直在两个平衡点之间来回）。
> 统一之后力场变成保守的，只剩**一个**平衡点 `F(y) = m × g_升`
> （200N / 10m / 质量 1 时 y = 8.12），阻尼能把振荡真正收掉。
> 判据是 `WindSensor.InField`（力 / 空气阻力 / 竖直阻尼有一项非零才算在场内，禁用的风场不算）。

### 9.4 参数（`WindZone` 上的序列化字段）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_forceAtBottom` | (0, 150) | 区域**底部**的风力（牛顿，世界坐标）。正值朝该轴正方向吹；力沿这个方向，大小随高度递减 |
| `_forceGradient` | 15 | **力的梯度**（N/m）：每上升 1 米，风力减少多少牛顿。0 = 恒定力。**相邻重力档的落点间距 `Δy = m·Δg ÷ 梯度`** —— 想让人在不同重力下分得更开就调小它 |
| `_drag` | 2 | 场内空气阻力（每秒速度衰减率），**水平 + 竖直都收**。**0 = 玩家会在平衡点附近永远弹射** |
| `_verticalDamping` | 8 | **竖直阻尼**（每秒速度衰减率），只收竖直轴、横向不动；与 `_drag` **叠加**。默认 ≈ 临界阻尼，被吹起来后不上下弹 —— 可随时调大 / 调小 |
| `_showEquilibriumLines` | true | 预览开关：Scene 视图里画出 ×削弱 / 正常 / ×增强 三条**平衡高度线**（按场景里玩家的质量与重力倍率算），纯编辑器辅助 |

组件上的序列化字段挂在 **Wind 层**（槽位 11），玩家侧 `_windLayer` 要指向它才算数 ——
与 `_solidLayer` 一样，**这是「这个实体能不能被风吹」的能力开关**。

### 9.5 风扇（`Fan`）—— 风道的实体载体

`Fan`（`Gameplay/Scene`）是 `IWindField` 的第二个实现，与 `WindZone` 是姊妹关系，但**心智模型不同**：

| | `WindZone` | `Fan` |
| --- | --- | --- |
| 一句话 | **这里有一块区域** | **从这里朝那边吹** |
| 几何 | 自己就是区域（碰撞体形状即范围） | 从扇体出发、沿**风向**延伸的矩形风道 |
| 力怎么衰减 | 沿**世界 y**（下 → 上） | 沿**离出风口的距离**（近 → 远） |
| 范围怎么调 | 摆碰撞体 | `_length` × `_width` 两个字段（Gizmo 随时画出来） |

它的受力规则、质量互动、与其它系统的关系**完全复用 §9.2 ~ §9.4 的结论** ——
报力、由实体除以质量、力沿出风方向按梯度衰减形成平衡点、有阻力才收敛。风扇只是把「区域」换成了「风道」。

参数（`Fan` 上的序列化字段）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `_direction` | `Up` | 朝哪吹（右 / 上 / 左 / 下）。**改字段，不要旋转对象** |
| `_length` | 10 | 风道长度：从扇体起沿风向吹多远（世界单位） |
| `_width` | 4 | 风道宽度：垂直于风向，以扇体中轴左右各一半 |
| `_force` | 150 | 出风口的风力（牛顿） |
| `_forceGradient` | 15 | **力的梯度**（N/m）：每远离出风口 1 米，风力减少多少牛顿。0 = 恒定力。间距 `Δy = m·Δg ÷ 梯度`（与 `WindZone` 同一套语义） |
| `_drag` | 2 | 风道内的空气阻力（水平 + 竖直都收），与 `WindZone` 同一个 `DragAt` |
| `_verticalDamping` | 8 | **竖直阻尼**，只收竖直轴、横向不动；与 `_drag` 叠加（与 `WindZone` 同一套语义，默认 ≈ 临界阻尼） |
| `_showEquilibriumLines` | true | 预览开关：**朝上吹时**在 Scene 视图画出三条平衡高度线（按场景里玩家的质量与重力倍率算） |

四条实现约束（都踩过或推演过）：

1. ⚠️ **必须落 Wind 层** —— 与 `WindZone` 一样，玩家的 `_windLayer` 只查这个层，放错层风扇白放、
   且没有任何报错。生成工具会自动设好，**手动复制粘贴风扇时注意别丢**。
2. ⚠️ **扇体碰撞体是「查询入口」，不是「碰撞」**：`WindSensor` 拿玩家碰撞体中心 `OverlapPoint`
   查 Wind 层的 trigger，命中后才会走到 `Fan.ForceAt`。所以碰撞体必须**罩住整条风道**，
   尺寸由组件按 `_length` / `_width` 自动同步（`OnValidate` / `OnEnable`）—— 别手改。
   真正的受力形状在矩形取样里，与碰撞体无关。
3. **方向是轴向枚举，不是任意向量**：风道与碰撞体严格一致 —— Scene 视图里选中风扇，
   看到的蓝框就是真实受力范围。要做斜向风再放开（`TrySample` 换成沿风向投影即可）。
4. **不旋转风扇**：风道与碰撞体都按 `_direction` 算，旋转对象只会让两者错位。

一键生成：菜单 `Tools/规则游戏/地图组件/② 风扇（吹出风场）`。

### 9.6 实测

| 验证项 | 结果 |
| --- | --- |
| `ForceAt` 线性插值 | 底 150N → 中 75N → 顶 0N，场外 0（逐点核对） |
| 力不随质量变 | 0.5 / 1 / 2 / 4 kg 四个质量读到的力**恒为 73.5N** |
| 加速度 = 力 ÷ 质量 | 同四点：147.0 / 73.5 / 36.7 / 18.4 —— **精确成比例** |
| 被风吹起 | 从 y=0 入场，一路加速升到 y=11.3（出场时 18.5 m/s） |
| 阻尼生效 | 下落速度被限制在「该高度的含风终端速度」：(mg−F)/c ≈ 12.5，实测 12.0 |
| 悬停 | 有阻尼后收敛到「风力 = **上升**重力」的高度（150N / 10m / 质量 1 → y = 7.5；风场内重力统一后） |

### 9.7 摆关卡注意

- ⚠️ **风场下方要有地形**。实测吃过一次：风场右半边悬在地面边缘外，
  玩家被托到边缘外就一路掉出地图 —— 风场区域是**判定**，不是**墙**，它不挡人不落人。
- 风场用 **trigger 碰撞体**，`Slide` 的 `useAttachedTriggers = false` 天然不处理它，不会挡人。
- 场与场可以重叠：多个风场的力与阻力**相加**（`WindSensor` 累加）。
- 组件被禁用的风场等于不存在（`ForceAt` 内部判 `isActiveAndEnabled`）。

### 9.8 与其它系统

| 情形 | 行为 | 理由 |
| --- | --- | --- |
| **在风场里** | **重力统一为上升重力**（不吃下落 ×2） | 方向依赖的重力是非保守力，会持续泵能量、让玩家在两个平衡点间自激振荡（§9.3） |
| 冲刺中 | **不积分风**（竖直与水平都不） | 保持「冲刺 = 平直横线」的既有读数 |
| 贴墙下滑 | **不积分风** | 竖直轴归墙独占，重力被屏蔽的地方风也被屏蔽 |
| 接地 | 风照常作用 | 风够强（F/m > g）自然把人吹离地面；⑥ 只抵消向下分量 |
| 暂停 | 天然冻结 | `FixedUpdate` 提前 return，**没有额外的暂停分支** |
| 时间规则 | 天然跟随 | 积分用 `Time.fixedDeltaTime` |

> **一句话规则**：**重力在哪不生效，风就在哪不生效。**
> 想改成「风吹得动贴墙的人」或「风把冲刺吹歪」，各自只需动一个分支。

### 9.9 还没做的

- **敌人侧**没接线（`EnemyMotor` 结构不同，接口已留好；`AddImpulse` 已经是 `÷mass` 的先例）。
- **动态刚体**（石头）不走这条通道 —— 它们该用引擎的 `AddForce`，引擎自动处理 F/m。
- 风场假定**静止**：判定读 `Collider2D.bounds`（缓存值），会动的风场要在移动后 `Physics2D.SyncTransforms()`。
