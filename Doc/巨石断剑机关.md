# 巨石断剑机关

> 一句话：**先踩地上的解锁按钮 → 重力反转把巨石举起来 → 碰到天花板上的按钮、被震裂 →
> 重力恢复、落地碎开 →
> 碎块里露出一把剑 → 走近（不用按键）自动拔出来。**
>
> 提出：策划（2026-10-18 会话）· 落地：2026-10-18（白盒占位，纯色块）
>
> 组件一览里的编号是 **⑫**，见 [关卡组件一览](关卡组件一览.md)。

## 1. 玩起来是什么样

| 步 | 玩家做什么 | 世界变成什么样 | 判据（代码里那一条） |
| --- | --- | --- | --- |
| ⓪ | 踩上地上的**解锁按钮** | 巨石从**静态**变成动态刚体 | `CitySwitch.PressByPlayerProximity` → `GravityBoulder.Unseal()`。**在此之前放多少次重力反转它都纹丝不动** |
| ① | 释放 **重力 × 反转** | 巨石（40 kg 动态刚体）往上飞 | 引擎的 `Physics2D.gravity` 被规则翻正，动态刚体自动吃 —— **本机关零特判** |
| ② | 等巨石升到天花板 | 巨石**穿过** CityButton 的触发区（按钮被按下），继续升到天花板顶住 | `IContactSwitch`：巨石认接口、按钮实现它 —— 接触式，**没有动量阈值** |
| ③ | （自动） | 按钮把巨石**震裂**（变红、标签改「巨石 · 开裂」） | `GravityBoulder.Touch()` → `Arm()` |
| ③′ | 规则还没结束 | 巨石**顶在天花板上**，**不碎** | ⚠️ 只有「接触点在巨石中心**下方**」才算落地（`IsSupportedFromBelow`） |
| ④ | 规则结束 / 主动取消 | 重力恢复，巨石从顶上砸回地面 | 落地速度 **10.2** > 阈值 6（从按钮高度落回来是 9.7，也够） |
| ⑤ | （自动） | 巨石碎成 8 块飞散，碎块里露出插着的剑 | `GravityBoulder.Shatter()`：撒碎块 + 把剑移到巨石底部正中 + 停用巨石 |
| ⑥ | 走到剑边 | 剑自己开始拔（0.45 秒动作） | 当前 `_requireFreeRule = 0`：只要求圈里有「玩家阵营」的实体 |
| ⑦ | 拔出完成 | 剑飞起 + 旋转，然后消失；玩家解锁攻击 | `SwordInStone._grantAbility = Attack` → `PlayerProgress.UnlockAbility` |

## 2. 为什么每一步都是必要的

**为什么必须先撞按钮才碎**（`GravityBoulder._requireArming`，默认开）
：否则「举起来再摔下去」就够了，天花板上的按钮纯属装饰，玩家根本不需要把石头举到那个高度。
把「震裂」挂在按钮上，两个动作才都成为必要条件。
（想要「摔下来就碎」的简化版，把这个开关取消即可 —— 那时按钮只当普通开关用。）

**判据是「落地速度」**
：石头质量是固定的，只需要回答「摔得够不够狠」—— 速度就够，而且**不受质量规则影响**，
于是「质量 × 削弱」不会意外变成第二把钥匙。

**⚠️ 为什么「撞到按钮上」绝不算落地**（踩过的坑，见 §10）
：两个条件缺一不可 ——
① **接触点必须在巨石中心下方**（从下面接住它）：顶到天花板 / 按钮时接触点在**上面**，不算；
② 速度取**自己**在物理步进前那一帧的向下速度，**不读** `Collision2D.relativeVelocity`。
后者是原来那版的写法，它的符号约定一记反，巨石被举起来顶到天花板那一刻就会被当成「落地」，
**石头在半空中就碎了** —— 就是你看到的那个 bug。

**为什么剑认「反转」不认「摩擦变小」**
：「摩擦 × 反转」只把方向标志 `FrictionInverted` 置位，倍率仍是 1；
而「摩擦 × 削弱 / 失效」改的是倍率。两者是**两把不同的钥匙**，
生锈齿轮（`RustyGear`）要的是「倍率 < 1」，本机关的剑要的是「反转」——
刻意错开，免得同一关里两个机关的解法撞车。
（真要改成认倍率，勾 `SwordInStone._acceptWeakFriction` 即可。）

**为什么石头推不动**
：巨石没挂 `PushableBody`，玩家顶它只是撞墙；而且 40 kg 远超玩家 60 N 推力对应的
约 12 kg 上限。它只能被规则举起来 —— 这是设计要的。

## 3. 组件一览

| 组件 | 住在哪 | 干什么 | 关键判据 |
| --- | --- | --- | --- |
| `GravityBoulder` | `Gameplay/Scene/` | 形态机：完整 → 开裂 → 已碎；落地碎开、撒碎块、露出剑 | 落地向下速度 ≥ `_breakSpeed`（6），且已开裂 |
| `BoulderFragment` | `Gameplay/Scene/` | 一块碎块：**纯表现** —— 炸出去、翻滚、向下射线找地面落地，然后停住。**没有碰撞体、也没有刚体** | 落地（射线打到 Ground 层）就停 |
| `SwordInStone` | `Gameplay/Scene/` | 插着的剑：拔出动作 + 解锁能力 | 当前 `_requireFreeRule = 0`（靠近即拔）；可选摩擦反转 + 圈里有玩家阵营实体 |
| `CitySwitch` | `Gameplay/Scene/Components/` | **复用既有组件**：积木城的 CityButton / 摇杆。**两个按钮都靠它**：天花板那个被巨石碰到（`IContactSwitch`），地上那个被玩家踩到（`PressByPlayerProximity`） | 接触 → `PressByContact()`；玩家靠近 → `SetOn(true)` |
| `ISwitchTarget` | `Gameplay/Common/` | 「被开关驱动的东西」接口。`CitySwitch.FollowMotor` 因此从 `CityPathMotor` 放宽到 `MonoBehaviour`：**拖门/电梯，或拖巨石**，配法一样 | `SetSwitchState(bool)` |
| `BoulderGateLock` | `Gameplay/Scene/` | **门锁**（2026-10-20）：挂在门上、绑一块巨石 —— 石头**碎开之前**门被按住，`OnShattered` 一到就开门。见 §11 | 只听 `GravityBoulder.OnShattered`，**不听天花板按钮**（那是上升途中顶到的） |

`GravityBoulder` 实现了 `ISwitchTarget` —— 所以**解锁的配法就是「把巨石拖到 CityButton 的 FollowMotor 上」**，
与配 Gate / 电梯完全同一条路径。

另外新加了 `PlayerLookup`（`Gameplay/Common`）——「这个东西算不算玩家」的唯一判据，
`CitySwitch` 的踩踏判定和 `SwordInStone` 的取剑判定都用它。

巨石还挂了 `RuleAffectedBody`（质量规则写进 `Rigidbody2D.mass`；
重力规则是全局的，不需要它）。

生成的层级：

```
BoulderSwordMechanism          ← 根：摆在「巨石中心静止时」的位置（离地 1.2）
├─ Boulder                     ← Ground 层、**开局是 Static**（锁死）、40 kg
│   ├─ Rim / Art               ← 出生点石砖放大（Art）+ 背后一圈黑影（Rim）
│   ├─ Label
│   └─ FragmentTemplate        ← **禁用中**，碎开时按它克隆一圈
└─ Sword                       ← **开局禁用**，碎开时移到巨石底部正中
    ├─ Art（Blade / Guard / Hilt）
    └─ Label

（关卡里另摆，不在这份预制体里）
CityButton ×2                  ← Prefabs/BrickCity/CityButton.prefab
   · 天花板那个（+6）：巨石升上去碰到它 → 震裂
   · 地上那个：玩家踩到 → 解锁（勾 PressByPlayerProximity，**把巨石拖到它的 FollowMotor 上**）
```

⚠️ **按钮为什么不打包进预制体**：它是积木城的公共组件，关卡里可能要摆好几个、要接门 / 电梯 /
炸弹（`CitySwitch.OnChanged`），打包进来反而不好复用。所以机关预制体只装「石头 + 碎块 + 剑」，
按钮自己拖。

**参数表**（都在 Inspector 上，不必改代码）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 巨石质量 | 40 kg | 推不动的门槛约 12 kg；调轻了玩家可能推得动 |
| 巨石尺寸 | 2.4 × 2.4 | 约 5×5 格 |
| 按钮高度 `LiftHeight` | 6 | 巨石升到 +6 就碰到按钮（触发区高 0.35，一物理帧只走 0.19，穿不过去）；从按钮高度落回来 9.7（阈值 6） |
| `_startAnchored` | 开 | 开局**锁死**（Static）：不吃重力、不被规则举、也摔不碎。防止玩家赶路时反复放重力反转把石头**提前震碎** |
| 解锁配法 | — | **把巨石（`GravityBoulder`）拖到地上那个 `CityButton` 的 `FollowMotor` 上** —— 与配 Gate 一样。没拖 = 一直锁着 |
| `PressByPlayerProximity`（按钮上） | 关 | 玩家走进触发区就按下。给地上的解锁按钮用（项目的交互键还没接进正式输入） |
| `_breakSpeed` | 6 | 落地速度阈值。从 1.8 米以上落下就碎 |
| `_requireArming` | 开 | 是否必须先被按钮震裂 |
| `_fragmentCount` | 8 | 碎块数量（均匀铺一圈，确定性，不掷骰子） |
| `_fragmentSpeed` / `_fragmentRing` | 3.2 / 0.7 | 炸开速度 / 生成环半径 |
| `_pullRadius` | 1.6 | 取剑半径（以剑尖为圆心） |
| `_pullDuration` / `_pullRise` / `_pullSpin` | 0.45 / 1.2 / 240 | 拔出动作（白盒占位） |

⚠️ **摆位**：根节点放在离地 **1.2** 处（巨石底面贴地）。摆歪了不会坏 ——
巨石是动态刚体，Play 之后自己会落到地面；只是上面那个 CityButton 的高度会跟着一起偏。

⚠️ **巨石必须在 `Ground` 层**（层 8）：玩家的 `Slide`、接地探测、
以及「落地」的层过滤（`_breakLayers`）都只认这一层。CityButton 无所谓（它靠接口认，不看层）。

⚠️ **CityButton 的碰撞体是 Trigger**：它**不挡**巨石 —— 巨石穿过去继续升，所以**天花板要自己摆**
（不然石头会飞出关卡顶部）。

## 5. 规则联动：一行特判都没有

| 规则 | 谁生效 | 为什么不用改代码 |
| --- | --- | --- |
| 重力 × 反转 | 巨石飞起来 | 规则直接写全局 `Physics2D.gravity`，动态刚体天然吃（与铁箱同一条路线） |
| 质量 × 增强 / 削弱 | 巨石的 `Rigidbody2D.mass` | `RuleAffectedBody` 自己读属性值写刚体 |
| 摩擦 × 反转 | （可选）剑松脱 | `_requireFreeRule = 1` 时才读 `FrictionInverted`；当前巨石预制体为 0，不参与 |
| 时间 × 任意 | 碎块的落定计时跟着停 | 碎块读 `TimeManager.DeltaTime` |

## 6. 怎么验

1. **edit 模式**：菜单 `规则游戏/验证/巨石断剑机关` → **34 项**断言，含
   「反转解锁 / 削弱不解锁」、「从下面接住才算落地」（那个 bug 的纯判据版）
   与「参数自洽」（把 `LiftHeight` 代进自由落体公式，检查这套摆位还砸得碎、
   一物理帧还穿不过按钮触发区）。**改常量之后先点它。**
2. **Play 模式**：打开 `Scenes/Test_BoulderSword.unity` → Play →
   `BoulderSwordSmokeTest`（**29 项**）会把整条流程自动走一遍：
   **锁死时放重力反转纹丝不动** → 踩解锁按钮 → 解锁 → 再放重力反转才举起来 → 碰按钮 → 震裂 →
   **顶在天花板上 2.5 秒不碎** → 落下来碎开 → 露剑 → 走近自动拔剑（不要求摩擦）。
   前两步和中间那步都是回归断言。逐条打 ✓ / ✗，报告同时落到
   `Project-Rule/Logs/BoulderSwordSmokeTest.txt`（Console 会被别的系统刷屏，文件更靠得住）。
   试验场景里的机关是**预制体实例** —— 验的就是关卡里拖进去的那一个；
   「玩家」是假玩家（静态碰撞体 + 玩家阵营），因为真玩家会被重力规则一起掀飞。
   ⚠️ 自动化跑之前记得 `Application.runInBackground = true`：编辑器**失焦时 Play 循环会停**
   （`Time.frameCount` 卡在 1），冒烟测试会一直卡在第一个 yield。

| 现在（纯色块） | 接美术时 |
| --- | --- |
| 巨石 / 碎块：白盒方块 + 颜色 | 换 Sprite；`GravityBoulder._art` 仍指向那个 `SpriteRenderer`（震裂换色可改成换图） |

`SwordInStone._onExtracted`（拿到剑：能力已由 `_grantAbility` 接好，这里留给音效 / 特效）。

## 9. 把剑接到「攻击能力」上（2026-10-19 已接线）

策划 2026-10-18 定的是：**剑取出来之后玩家才有攻击能力**。

> **2026-10-19 更新**：`SwordInStone` 新增 `_grantAbility`（默认 `Attack`），拔出时经
> `PlayerProgress.UnlockAbility` 解锁；`BoulderSwordMechanism.prefab` 的 `_requireFreeRule` 已设为 0
> —— 石头碎掉、剑露出来后，玩家**走进 1.6 米就自动拔**，不需要摩擦、也不需要攻击键。
> 整体方案见 [能力与词条解锁](能力与词条解锁.md)。
> 下面这张表保留作接线记录。

| 接线点 | 现在的实现 |
| --- | --- |
| `SwordInStone._grantAbility`（默认 `Attack`） | 拔出完成时 `PlayerProgress.UnlockAbility(_grantAbility)`；`_onExtracted` 留给音效 / 特效 |
| `PlayerController.FixedUpdate` 第 ③′ 步 | `bool attackPressed = input.AttackPressed && HasAbility(PlayerAbility.Attack);`，轻击 / 重击都用它 |

**已定（策划 2026-10-18）**

- ✅ **解锁状态存在玩家自己的属性里**：与「每个能力都是实体自己的序列化字段」同一条约定 ——
  写在玩家身上（`PlayerController` 序列化字段那一路），**不新开系统**，也不要塞 `IRuleUnlocks`
  （它管的是「属性 × 关系」**词条**解锁，语义不同）。

**还没定的**

- ⬜ 开局没有攻击怎么表达：教学提示？HUD 灰掉攻击键？还是关卡里本来就没敌人所以无所谓。
- ⬜ 敌人要不要也受「没剑不能打」限制。按现有架构，攻击能力是**实体自己的能力**，
  所以玩家侧这道门应该开在**玩家控制器**上，而不是战斗系统里。
- ⬜ 重开关卡 / 读档时剑已经取过 → 攻击能力直接给（存档只存「已解锁」这类小数据，约束 C5）。

## 10. 踩过的坑 / 实现约束

- ⚠️ **碎块不能有碰撞体**：它们会堆在剑周围，实心的话玩家走过去会被**卡住 / 顶起来**（实测过）。
  所以 `BoulderFragment` **没有 Collider、没有 Rigidbody**，自己积分（重力取 `Physics2D.gravity`，
  跟着重力规则飘）+ 向下射线找地面。代价是瓦砾**不挡路、也站不上去** —— 这是要的。
  顺带一个好处：它们也不会挤进 `SwordInStone` 的取剑探测圈。
- ⚠️ **碎块生成前先关掉石头自己的碰撞体**：碎块的落地射线是从碎块中心往下打的，
  石头碰撞体还在的话会从内部打到自己、碎块当场贴在原地。
- ⚠️ **锁死 = `RigidbodyType2D.Static`**：静态刚体不吃重力、也不发碰撞回调，所以「没解锁就碎」不可能发生。
  代价是**巨石会被当成一块地形**（能站、能挡路）—— 这是想要的。
  ⚠️ 换类型前要先把速度清零（静态刚体不接受速度写入）。
- ⚠️ **没把巨石拖到按钮的 `FollowMotor` 上 = 石头永远动不了**（它一直在「巨石 · 锁死」）。
  按钮那边还要勾 `PressByPlayerProximity`，否则玩家踩上去没反应（交互键还没接进正式输入）。
  `FollowMotor` 拖了不支持的东西（既不是 `CityPathMotor` 也没实现 `ISwitchTarget`）会打一条警告。
- ⚠️ **落地判据不能用 `Collision2D.relativeVelocity`**（2026-10-18 修的 bug）：它的符号约定
  一记反，巨石被举起来顶到天花板那一刻就会被当成「落地」——**石头在半空中就碎了**。
  现在只看两件事：① 接触点在巨石中心**下方**（`IsSupportedFromBelow`，纯函数版是 `IsContactBelow`）；
  ② **自己**在物理步进前那一帧的向下速度（`_peakFallSpeed`，在 `FixedUpdate` 里记）。
- ⚠️ **CityButton 的碰撞体是 Trigger**：它会被按下、但**不挡**巨石 —— 巨石穿过去继续升，
  所以关卡里**天花板要自己摆**，否则石头飞出关卡顶部。按钮自己也**不扫描**：
  是压过来的那一方（巨石）在触发回调里调 `IContactSwitch.PressByContact()`。
- 巨石**必须 Dynamic**，而且 `sleepMode = NeverSleep`：睡着的刚体不响应重力变化，
  会在重力反转后原地悬空（与铁箱同一处理）。
- 碎块模板**必须禁用**，否则它自己也会掉下来。
- 碎块根物体**缩放必须是 1**、尺寸写在 `BoxCollider2D.size` 上，
  白盒精灵单独缩放 —— 否则碰撞体比外观小一半。
- 碎块落定后变 Static 是为了省钱、也为了不让满地的瓦砾跟着重力规则再飞一次；
  变 Static 之后**碰撞体还在**，瓦砾堆天然可以站。
- 玩家是 Kinematic 刚体 + `Slide`（`useAttachedTriggers = false`），
  所以取剑的「有人在旁边吗」**自己扫圈**，不用触发器回调（与按钮 / 弹簧同一做法）。
- 「谁算取剑的人」认的是 `PlayerController` 或 `IFactionMember.Faction == Player`，
  不认具体类型 —— 敌人站在旁边拔不动。

## 11. 门锁：碎掉之后才开（2026-10-20）

关卡里那扇门（`Level_Start_01` 的 `CityGate (4)`，就在巨石竖井口）要**等石头碎掉**才让进。
用的组件 `Gameplay/Scene/BoulderGateLock.cs`：挂在**门**上，把巨石拖进 `_boulder`。

| 项 | 做法 |
| --- | --- |
| 什么时候解锁 | 只听 `GravityBoulder.OnShattered`（**落地碎开那一下**） |
| 解锁后 | 默认立刻 `CityPathMotor.SetOn(true)` 把门拉开；取消 `_openOnUnlock` = 只解锁、等别的机关来开 |
| 锁着的时候 | `_holdClosedWhileLocked`（默认开）在 `LateUpdate` 把门的目标端扳回关位 —— 就算还有别的开关连在这扇门上，也开不了 |
| 存档 | 解锁写进 `WorldStateStore`（槽位 `#unlocked`）：**巨石不进存档，门要进** |

⚠️ **不要把门拖到天花板按钮的 `FollowMotor` 上**：那个按钮是巨石**上升途中**被顶到的，
那一刻石头还顶在天花板上、离碎开还有一整段。挂在按钮上，玩家能提前钻进碎石区，甚至被落下来的石头砸中。
天花板按钮现在只负责**震裂**（`GravityBoulder` 自己认 `IContactSwitch`，与 `FollowMotor` 无关），
门改由 `BoulderGateLock` 驱动 —— `Level_Start_01` 里那个按钮的 `FollowMotor` 已经清空。

⚠️ **为什么解锁要进存档**：巨石是「地形」，不参与回溯也不落盘，读档回来它会重新变完整。
门要是跟着石头一起重置，已经拿过剑的玩家就会被一扇永远打不开的门堵在外面 —— 所以门自己记住「已经开过了」，
`Start` 里查到就直接开。
