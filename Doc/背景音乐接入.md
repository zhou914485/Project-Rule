# 背景音乐接入

三套区域音乐由 `RuleGame.Presentation.Audio` 驱动。`LevelRuntime.prefab` 已挂载 `MusicDirector`，Boot 中的常驻 GameRoot 通过嵌套预制体继承该组件；序章和中心区暂用积木音乐。三个主题的正式地图尚未全部登记到分区表，音乐归属通过区域矩形配置，不根据场景名或预加载事件推断。

## 播放行为

- 积木、发条：本次运行首次进入播放前奏，再进入循环。返回已经访问过的区域直接播放循环。
- 毛绒：整曲循环。
- 跨区域：默认 1.5 秒平滑交叉淡化。新曲先准备好音频并预留 0.5 秒 DSP 排程时间，旧曲在这期间继续播放。
- 边界：保留当前区域至超出边界 1 米，新归属稳定 0.25 秒后才请求切换。重叠区域优先使用更高的 Priority。
- 连续跨越多个区域时，新请求保留为最终目标；已经参加淡化的曲目可反向淡化，第三首等待当前淡化结束，避免截断仍可听见的音乐。
- 暂停：订阅 `ITimeManager.OnPausedChanged`，用非缩放时间平滑压低到正常音量的 35%，音乐继续。恢复暂停后回到原音量。
- 时间规则不改变音乐速度和音高。音乐不进入世界快照，回溯后根据玩家位置重新判断区域。
- 不改变 `AudioListener.pause`、`Time.timeScale` 或任何伤害、规则与存档逻辑。

```mermaid
flowchart LR
    A[玩家位置] --> B[MusicRegion 区域矩形]
    B --> C[迟滞与稳定时间]
    C --> D[MusicDirector]
    P[MusicProfile 前奏与循环配置] --> D
    T[TimeManager 暂停事件] --> D
    D --> E[两组前奏与循环声源]
    E --> F[DSP 衔接与交叉淡化]
```

## 地图接入

1. 保留 Boot / GameRoot 已有的常驻 `LevelRuntime`，不要在每个流式分区里额外放一套播放器或 AudioListener。
2. 从 `Assets/_Project/Prefabs/Audio/` 拖入 `Bricks_MusicRegion`、`Clockwork_MusicRegion` 或 `Fluffy_MusicRegion`。
3. 把区域物体移到对应地图中心。在 Scene 视图选中后拖动蓝色矩形手柄，或在 Inspector 修改 Size；不需要碰撞体。位置、旋转和缩放均由物体 Transform 决定。
4. 同一个主题的多个分区复用同一份 MusicProfile，区内移动不会重新开始音乐。特殊小区域可提高 Priority。
5. 未覆盖的位置使用 `MusicDirector.DefaultProfile` 的序列化配置；当前为积木区。停用或卸载区域后会重新解析归属。

配置位于 `Assets/_Project/Data/Audio/`，每份可以调整 Volume 和 Crossfade Seconds。三地区游戏音量现统一为 0.25（原0.65，约降低8.3dB），新建MusicProfile默认也为0.25；暂停继续按这个较低基准压至35%。播放器的 Boundary Hysteresis、Region Delay、Paused Volume、Duck Seconds 和 Schedule Ahead 均可在 LevelRuntime 的 Inspector 中调整。

## 素材与导入

原始交付的五份 OGG 完整保存在 `Doc/AudioSources/MusicOriginals/`，SHA-256、采样长度和处理结果见 `Doc/AudioSources/MusicManifest.json`。播放用 WAV 位于 `Assets/_Project/Audio/Music/`，保持双声道和 44.1 kHz，不调整开头或增益。

源文件含较长的导出尾部近静音。处理脚本只去掉低于 -60 dBFS 的连续尾部，并在最后可听样本后保留 20 ms：

| 曲目 | 原始时长 | 播放时长 |
| --- | ---: | ---: |
| 积木前奏 | 12.325 秒 | 11.141 秒 |
| 积木循环 | 99.805 秒 | 87.947 秒 |
| 发条前奏 | 5.406 秒 | 2.776 秒 |
| 发条循环 | 75.906 秒 | 61.991 秒 |
| 毛绒整曲 | 81.559 秒 | 79.378 秒 |

这样可去掉循环间长达十余秒的空档。音乐节拍、混响尾音与首尾乐句仍按交付素材保留；本次处理没有重新编曲或自动推断节拍循环点。

重新处理新的交付文件：

```sh
python3 Tools/Audio/prepare_music.py '/绝对路径/背景音乐(4)'
```

脚本需要本机 ffmpeg。Unity 中运行 `Tools → 规则游戏 → 音频 → ① 接入三地区域音乐`，会通过 Editor API 更新导入参数、三份配置、三个区域预制体及 LevelRuntime 接线。重复运行保留已有的音量、淡化时间和区域矩形。长曲使用 Streaming，前奏使用 Decompress On Load，启用预载；Vorbis 导入质量为 1，保持采样率和双声道。

## 试听与验证

打开 `Assets/_Project/Scenes/Test_AreaMusic.unity`，直接 Play。玩家从积木区开始，向右依次进入发条区和毛绒区；每区宽 20 米，主题交界在 x=-10 和 x=10（从积木区中心 x=-20 出发）。打开规则轮盘可检查暂停音量。

菜单 `Tools → 规则游戏 → 音频 → ③ 验证背景音乐（PlayMode）` 会记录当前已保存场景，进入临时空场景执行检查，退出 Play 后自动恢复原场景。请先保存自己的场景修改。

2026-10-18 在 Unity 6000.6.4f1 的原工程 Editor 中，37 项定向检查通过：真实播放采样推进、两组前奏接循环、积木与毛绒循环回绕、两路非零音量交叉淡化、暂停与慢时间、预加载不换曲、边界迟滞、回访不重播前奏、快速切区、区域停用及播放器重新启用。结果保存在本地 `Project-Rule/Logs/AreaMusic/Validation.txt`。源文件哈希和派生 PCM 采样长度也已核对。验证未执行完整 Player 构建或目标设备听感验收。
